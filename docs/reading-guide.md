## 一篇笔记怎样读

每篇精读先从“阅读起点”开始：解释摘要中首次出现的专业术语，按原段落完整
翻译摘要；读者先知道作者实际声称了什么，再看“为什么今天值得读”，了解
新近性、影响/社区信号、作者与团队脉络、覆盖价值及同轮候选对照，然后进入
同一条五段教学路线：

1. **看原图**：先建立方法的空间结构和信息流；
2. **读原式**：逐符号理解论文真正定义了什么；
3. **看结果**：判断数字是否支持作者主张；
4. **对源码**：核对公式在固定 commit 中怎样实现；
5. **记结论**：留下贡献、证据边界和开放问题。

读者可以在三处自然停下：5 分钟读完选择理由、摘要与首图；30 分钟读完机制、
原式、结果和消融；研究级继续核固定源码、复现账本和相邻工作。首页只提供
“今日精读 + 今日 Taste”短入口，历史论文分别进入
[全部精读](../index/papers.md)和[主题路线](../index/topics.md)。

## 为什么今天读这篇

从 2026-08-06 起，摘要后的选择卡是新笔记的强制部分。它不能只写“热门”或
“来自名校”，而要分别给出权威录用链接、带日期的影响/采用信号、官方团队来源、
P01–P13 覆盖价值和本轮强候选对照。GitHub Star、引用、帖子热度和机构声誉只
帮助发现与排序，不能替代论文的受控证据、源码完整度和感知研究贡献。

完整候选漏斗、10 分制权重和经典论文例外见
[每日选文与研究缺口核查协议](daily-selection-and-gap-audit.md)。

## 整体算法架构与创新主线

第 1 部分不是只贴一张方法图。每篇笔记都必须建立一条可核验的设计因果链：

> 原方法的具体瓶颈 → 作者为什么需要新的结构 → 继承的 backbone / baseline
> → 本文真正新增的模块 → 端到端信息流 → 训练监督与损失 → 逐模块实验和源码。

首先写清输入端 backbone、neck / encoder、中间表示和 prediction heads。若作者
基于现有系统改造，必须明确区分“基础模型本来就有的能力”和“本文新增、替换或
重新训练的组件”；不能把整套系统结果都归因给论文新模块，也不能把某个
ViewFormer、ResNet 或预训练组件误写成作者原创。

每个关键创新使用适合手机和 iPad 纵向阅读的竖向卡片。神经网络方法称为
“创新模块”；数据集、训练范式、系统或评测论文称为“创新单元”，不能为了
套模板伪造网络模块。卡片按从 1 开始的连续阿拉伯数字编号，并逐项说明：

- 它位于架构的哪里，与上下游接口是什么；
- 输入张量、历史状态、坐标、mask 或辅助信息是什么；
- 内部按什么顺序完成采样、对齐、注意力、融合或更新；
- 输出交给哪个 head、状态或后续任务；
- 作者面对什么瓶颈，为什么会想到这样设计、为什么把模块放在这里；作者
  明说的动机标 **[论文]** 并给页码，笔记从瓶颈重建的因果链标 **[判断]**
  且明确声明不是作者原句；
- 模块由什么监督和损失训练，训练与推理所见信息是否相同；
- 哪个独立消融或受控对照支持它的作用；
- 论文页码和固定 commit 中的真实源码入口。

“作用与证据”必须落到带编号 Table / Figure 中的消融或受控比较，并写出
指标、数值或变化方向；方法结构图本身不是效果证据。若原文没有某模块的独立消融，使用
**[未核验]** 明确写“原文未提供独立消融，不能把全模型增益单独归因给该
模块”。如果论文图、公式和代码对同一状态或运算的表述不同，则三者并列说明，
不为追求故事完整而强行宣称逐值等价。架构部分禁止任何 Markdown / HTML
表格；Section 4 只核对这些模块在源码中的实际落点、状态读写和实现差异，
避免重复讲一遍方法。

## 翻译、术语与来源锚点

### 摘要必须完整翻译

摘要译文不是 TL;DR。它必须覆盖原摘要全部实质句子和段落，保留：

- 问题定义、方法、实验和结论之间的论证顺序；
- `may`、`can`、`significantly` 等限定强度及否定、比较和因果关系；
- 数据集、指标、数值、单位、公式符号和引用标记；
- 作者对贡献范围的限制，不能把“在某设置下有效”扩大成普遍结论。

译文使用 **[原文翻译]**，只表达作者原意。为了初学者理解而增加的类比、
背景和一句话解释使用 **[笔记解释]**；批评、外推、研究启发和可检验假设
使用 **[判断]**。后两者不得插进译文段落。

每个译文段落必须标出原文章节、PDF 页码和稳定锚点。例如摘要使用 `A01`、
`A02`，结论使用 `C01`、`C02`，局限使用 `L01`，展望使用 `O01`。后续修订
已有笔记时尽量不改变锚点，使索引、讨论和核验记录可以稳定回指。PDF 页码
统一指 PDF 阅读器显示页；若论文印刷页码不同，可同时注明 proceedings 页。

### 专业术语首次出现时先解释

摘要前建立一个适合手机与 iPad 纵向阅读的紧凑术语先导列表。对于摘要之后
才第一次出现的术语，在正文
首次出现处使用以下形式：

> 领域通行中文名（English full term, ABBR）：一句话说明它是什么，以及它
> 在这篇论文中承担什么角色。

术语选择遵守以下规则：

- 优先采用自动驾驶、计算机视觉、机器人和机器学习领域已经通行的中文译法；
- 不能脱离本文任务、坐标系或评测语境逐字硬译，也不能为追求口语流畅而随意
  意译；
- 模型名、方法名、模块名、数据集名和 benchmark 名通常保留作者原名，并
  说明其类别和作用；
- 英文缩写在第一次出现时展开一次，后文使用同一缩写；
- 符号、大小写、连字符和单复数含义保持一致；同一概念不能在不同章节换译名；
- 没有可靠通行译法时保留英文，给出中文解释，不自行发明听起来像正式术语的
  新译名。

### 结论、局限和展望必须完整翻译

第 5 部分必须忠实翻译作者公开的 Conclusion、Limitations 和 Future Work /
Outlook 或同义章节的全部实质段落。若局限或展望散见于 Conclusion 或
Discussion，只翻译相关的连续原文段落，并保留必要上下文，不能从多处挑一句
拼成作者没有写过的“完整结论”。

如果论文没有独立结论、局限或展望，明确记录“论文未设置独立章节”或“作者
未提出明确未来工作”。本笔记发现的局限和建议另放在 **[判断]**，绝不冒充
作者原话。

没有独立 Conclusion 时，仍可翻译真实承担收束作用的 `Discussion`、`Summary`
或 `Concluding Remarks` 连续段落：译文头保留真实章节名，稳定锚点继续使用
`C01`、`C02`，并先用 **原文缺失声明** 写清检查范围和“不冒充 Conclusion”
边界。Limitations 与 Future Work 是否缺失必须分别声明，不能用一句含混的
“原文没有相关章节”同时代替两项核验。

## 实验配置与实验流程

只要主论文、附录、补充材料、项目页或官方固定 commit 公开了实验信息，第 3
部分就必须详细说明，而不是只摘最终结果表。至少逐项核对：

1. 数据集版本、train/val/test 划分、标注构造与过滤规则；
2. 传感器、帧数、输入范围、分辨率、坐标系、预处理与数据增强；
3. 训练硬件、软件环境、关键依赖、初始化或预训练权重；
4. 优化器、学习率、scheduler、batch size、训练 epochs/steps 和损失权重；
5. 随机种子、重复次数、验证频率、模型选择与 checkpoint；
6. 推理时状态管理、阈值、后处理、测试时增强和运行精度；
7. benchmark protocol、指标定义、基线统一设置及最终评测入口。

随后按“数据准备 → 训练 → 验证和选模 → 推理和后处理 → 最终评测”复述可公开
的实验流程。每一项都附论文 PDF 页、附录/补充材料章节或固定 SHA 源码链接：

- 正文、附录或补充材料直接报告的内容标为 **[论文]**；
- config、脚本或 README 在固定 commit 中直接支持的内容标为 **[源码]**；
- 论文和源码值不一致时并列记录差异，不能静默替换；
- 没有公开的设置写明“原文未公开”或“源码未公开”；
- 没有实际运行的步骤写明 **[未核验]**，不能把“配置存在”写成“已经复现”。

如果公开信息不足以闭合完整流程，最后列出“复现仍缺什么”，不得按领域惯例
猜测硬件、超参数、随机种子或评测设置。

## 图表规则

- 第 1 部分至少保留一张真正决定理解的原文方法图，第 3 部分至少保留一张
  支撑主张的原文结果表；
- 只截取必要图表，不保存或重新发布整篇 PDF；
- 图片存放在 `assets/notes/<note-key>/`，不能依赖会失效的外链热链；
- 每张图都写明原文 Figure/Table 编号、PDF 页码、官方原文链接与权利归属；
- 每张图后第一个非空内容必须是其“原图出处”块，关键图表不放进折叠区；
- 图片必须有可读的替代文本，并在提交前按 GitHub 页面宽度人工检查；
- 原图只用于必要的学术评论与讲解，版权归原作者及其他权利人。

如果某篇论文的许可或图像复用条件不清晰，优先制作自己的解释图并链接原图，
不要把整页论文或大量图表复制进仓库。

## 公式规则

GitHub 官方文档说明，Markdown 数学公式由 Web 界面的 JavaScript MathJax
组件呈现。GitHub 原生移动 App 不保证执行同一套网页组件；实际设备上可能把
`math` fence 或 inline TeX 当成普通代码。为保证浏览器、GitHub iPad/iPhone
App、深色模式和读屏场景得到同一内容，精读正文不依赖 live MathJax。

[GitHub 官方数学表达式说明](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/writing-mathematical-expressions)

本仓库采用三层交付：

1. **公式图**：同一份 TeX 生成内容紧裁的 2× light/dark PNG pair，正文按
   公式的自然尺寸居中显示；
2. **纯文字读法**：图片失败或使用读屏时仍能理解公式语义；
3. **TeX 源**：放在该笔记 `formulas/source.tex`，供复制和逐项核对。

正文结构固定为：

````text
**原文公式：** 论文 Eq. (7)，PDF p. 4。

<p align="center"><picture><source media="(prefers-color-scheme: dark)" srcset="../../assets/notes/<note-key>/formulas/eq-07-class-update-dark.png"><img src="../../assets/notes/<note-key>/formulas/eq-07-class-update-light.png" alt="公式：Eq. 7，类别状态递推更新" width="480" height="84"></picture></p>

> **公式来源：** 作者、编号、PDF 页、官方 PDF、按原符号重排说明、
> [可复制 TeX](../../assets/notes/<note-key>/formulas/source.tex)。

**纯文字读法：** 下一时刻的类别状态 ***c***<sub>*t*+1</sub>，由当前状态
***c***<sub>*t*</sub> 与历史状态融合后归一化得到。
````

维护时必须遵守：

- `notes/` 和 `templates/` 中不使用 inline dollar math、fenced `math`、
  TeX 括号分隔符或双 dollar block；
- 普通行内数学使用 Unicode 符号、Markdown 斜体或粗斜体，并用
  `<sub>` / `<sup>` 表示上下标，例如 *M*<sub>*t*</sub>、
  *δ*<sub>*p*</sub>、*p* + ***f***<sub>*p*</sub>；反引号只用于
  `update_global` 这类真实源码标识、命令、路径或配置值；
- 每张公式图使用准确、非 LaTeX 堆砌的中文 alt text；
- 公式图后的第一个非空内容必须是连续的“公式来源”引用块；
- 每个块级公式必须由同一个 TeX 命名块一次生成 light/dark 两张 PNG；
  两图内容、裁切和像素尺寸必须一致，只改变背景与前景色；
- PNG 按公式墨迹紧裁、保留一致的安全边距并以 2× 像素密度导出；正文使用
  GitHub 可解析的单行 `<p><picture>…</picture></p>`，在 `<img>` 上显式写
  自然显示 `width` / `height`，不得把短公式强行铺满正文；
- 长公式按语义主动换行，不能靠缩小字体塞进一行；light 图作为不支持
  `<picture>` 主题切换时的可读 fallback；
- 原文公式标明 Eq. 编号、PDF 页码和源码映射；
- 原文没有编号时明确标“原文未编号公式”并给 PDF 页码，不自行补编号；
- 论文自定义宏先展开，再进入独立 TeX 源；
- 笔记自己的推导或量级估算明确标成“[判断] 非原文公式”；
- 如果论文没有不可替代的关键公式，明确说明，不为满足模板而编造；
- 关键原式保持在正文可见区域，不放进 `<details>`；
- 公式 PNG、TeX 命名块和正文引用必须一一对应，不能留下孤儿资产；
- 类比之后必须回到正式符号、论文定义和证据边界。

发布前运行：

```bash
python scripts/render_formula_assets.py --check
python scripts/rebuild_index.py
python scripts/rebuild_index.py --check
python scripts/lint_markdown_math.py
python -m unittest discover -s tests -v
```

分支推送后，公开页面 smoke test 还会在桌面与 iPad 尺寸、浅色与深色主题下
检查：对应主题公式图全部加载、显示尺寸与 2× 原图匹配、短公式不过度拉伸、
页面不存在 `math-renderer`，正文没有横向溢出。

## 证据边界

- **[原文翻译]**：保留作者原意、论证强度和来源位置的专业中文译文；
- **[笔记解释]**：为理解原文增加的术语说明、背景或教学类比；
- **[论文]**：论文、补充材料或权威 proceedings 可以直接支持；
- **[源码]**：固定 commit 的官方代码可以直接支持；
- **[判断]**：基于前两类证据的解释、批评或推断；
- **[未核验]**：尚未运行、复现或向作者确认。

“源码已读”不等于“结果已复现”，“时间更稳定”也不自动等于“预测更正确”。
