# 每日选文与研究缺口核查协议

[返回首页](../README.md) · [选文规则](../SELECTION_POLICY.md) ·
[开放问题](../index/open_questions.md)

这份协议回答两个最容易被含混处理的问题：**为什么今天读这篇**，以及
**笔记提出的下一步是否已经有人做过**。它从 2026-08-06 起适用于全部新精读；
旧笔记不追溯补写未经当时检索支持的“新颖性”结论。

## 1. 每日候选漏斗

### 第一层：优先近一两年的正式顶会内容

候选池先看当前与前两个会议年份，并对最近 24 个月正式录用的工作再加优先级。
录用身份只能由 CVF / ECVA、OpenReview decision、PMLR、NeurIPS proceedings、
IEEE、ACM、Springer 或期刊官方页面确认。arXiv、项目页、帖子和 GitHub README
只能帮助发现候选，不能单独把预印本升级成“顶会论文”。

三到五年前的论文只有在下面至少一项成立时进入前排：它已成为后来工作的直接
基础；它定义了仍在使用的任务、表示或评测；它能补上 13 类中长期缺失的关键
方向；它暴露的核心假设在新工作中仍没有被解决。更早的经典论文必须明确写出
“为什么现在仍值得读”，不能以引用量替代今天的研究价值。

### 第二层：质量、影响与开放空间共同排序

每篇候选按 10 分制排序：

- **新近性与录用质量，0–2 分：** 最近 24 个月正式顶会/顶刊优先；重要经典
  例外需要给出后续依赖证据。
- **感知相关性与覆盖价值，0–2 分：** 必须有可定位的感知问题、指标或系统
  接口；同时优先长期未读但存在强候选的主方向。
- **影响与社区信号，0–1.5 分：** 看后续论文采用、benchmark 影响、官方代码
  使用、奖项/口头报告和时间归一化引用；GitHub Star 与帖子热度只能作为注意力
  信号，不能作为论文正确性的证据。
- **作者与团队研究脉络，0–1 分：** 优先持续产出该方向关键工作的作者、实验室
  与工业研究团队，并从官方作者页、机构页和论文 affiliation 核验。MIT、CMU、
  Stanford、Berkeley、ETH、Tübingen/MPI、Toronto、Oxford、Cambridge、清华、
  北大、上交、浙大、上海 AI Lab、Waymo、NVIDIA、Toyota Research、Motional、
  Waabi 等只是非穷举的观察入口；机构名望不能替代方法、证据与源码质量。
- **公开材料与源码完整度，0–1.5 分：** 正文、补充材料、官方仓库、配置、
  checkpoint、许可证和可运行入口越完整，越适合深读。
- **研究决策与创新空间，0–2 分：** 优先能改变研究判断、揭示可证伪假设、
  提供可迁移接口或让一个重要边界变得可测的工作。只有完成第 3 节的相邻工作
  核查后，才可以把某个差异作为“仍值得研究”突出显示。

默认选择 7 分及以上候选，8 分以上优先。轮换只改变搜索顺序，不允许为了填满
13 类降低录用、证据、源码和研究价值门槛。团队背景只用于强候选之间的排序，
不能把非名校、非大厂但证据更强的论文降到后面。

### 第三层：笔记公开“为什么是它”

新笔记必须在摘要完整翻译及一句话教学导读之后、第一张方法图之前回答：

1. **新近性与录用：** 年份、venue、权威录用链接；若是经典例外，解释例外。
2. **影响与社区信号：** 写查询日期与来源，区分学术证据、工程采用和热度。
3. **作者与团队脉络：** 用官方 affiliation / 作者页说明该团队为什么值得跟踪，
   同时明确这不是论文质量证明。
4. **覆盖与研究价值：** 指出对应 P01–P13、上次精读日期和会改变的研究判断。
5. **候选对照：** 至少列出同一轮中最接近的强候选，解释为什么今天先读这一篇。

## 2. 面向不同读者的三遍入口

仓库把一篇精读拆成三种可停下来的阅读深度：

1. **5 分钟判断值不值得继续：** 看“为什么今天值得读”、完整摘要译文、第一张
   方法图和一句话证据边界。
2. **30 分钟真正理解机制：** 沿架构信息流、原式、小数字例子、主结果和关键
   消融读到“证据支持 / 没有支持”。
3. **研究级核验：** 打开固定 commit，追入口、配置和状态读写，再看论文—源码
   差异、复现账本与相邻工作核查。

这种分层不删减内容，而是让手机读者可以在每一遍结束时已经得到一个完整答案。

## 3. “下一步是否已经做过”的强制检索

开放问题不是一句宽泛的“未来可以研究”。每个准备公开突出显示的问题都执行
以下步骤。

### 3.1 先把主张拆成四个可比较轴

- **问题轴：** 具体缺陷、风险或未解释现象是什么；
- **机制轴：** 拟验证的模块、训练信号、状态或系统接口是什么；
- **洞见轴：** 预期新增的因果解释、测量或能力是什么；
- **场景轴：** 数据、传感器、坐标、时序、部署或安全条件是什么。

如果主张无法拆成这四轴，就还不足以声称存在明确研究空白。

### 3.2 至少执行三路检索

1. **机制词检索：** 方法名、模块、损失、状态或接口的准确术语；
2. **问题词检索：** 不带自拟方法，从失败模式、任务与评测问题反向搜索；
3. **同义词与邻域检索：** 替换术语、缩写和相邻领域说法，避免只搜到使用同一
   命名的工作。

检索同时覆盖正式 proceedings、OpenReview / PMLR / IEEE / ACM / Springer、
arXiv、Crossref / OpenAlex / Semantic Scholar 类索引、官方项目仓库、作者与
实验室主页。热门帖子、Awesome List 和社交讨论用于扩大召回，最终覆盖判断
必须回到论文原文、补充材料和官方源码。

### 3.3 核对最接近工作，而不是只看标题

先用标题和摘要去重，再对最接近的 3–7 篇读 Method、Experiments、Limitations
与补充材料，必要时核官方源码。逐篇记录四轴中哪些相同、哪些不同；不能因为
数据集或模块名不同，就跳过本质上相同的问题与机制。

### 3.4 只允许四种覆盖判断

- **[已覆盖]：** 已有工作在关键四轴和主要证据上直接覆盖；不再把它突出为缺口。
- **[部分覆盖]：** 已有工作解决了主体，只保留可明确验证的剩余差异。
- **[本次检索未找到直接覆盖]：** 在公开的日期、来源、检索式与阅读范围内没有
  找到四轴同时匹配的工作；可以突出，但必须同时显示范围边界。
- **[检索受阻]：** 网络、资料或全文不可得；保留分支/PR，不发布“尚未做过”判断。

公开措辞统一使用“截至 YYYY-MM-DD，在列明来源与检索式内，本次未找到直接
覆盖”，禁止写“学界没人做过”“首次有人想到”或“确定空白”。如果最接近工作
只覆盖一部分，突出的是**可核查的差异**，不是对全领域的排他性宣称。

### 3.5 时效与复核

准备在首页、开放问题雷达或下一篇笔记再次突出一个缺口时，若上次检索超过
30 天，或期间出现新会议批次、预印本和代码发布，必须重查。论文投稿或形成
具体新方法之前，还需要做独立、范围更广的新颖性核查；本仓库的日常检索不能
替代正式 prior-art review。

## 4. 合并门槛

从 2026-08-06 起，新精读缺少“为什么今天值得读”或“开放问题的相邻工作检索”
任一字段，检索结论为 **[检索受阻]**，最接近工作没有官方链接，或公开边界把
有限检索写成全领域“无人做过”，`rebuild_index.py` 必须失败。网络、CI 或资料
故障时保留可审查分支/PR，不能为了完成日更绕过检查。
