# SOTA 与跨领域迁移雷达：口径、检索和日更方法

这两个雷达解决两个不同问题：

- [SOTA 与指标雷达](../sota/README.md)回答“在一个说得清楚的公开协议里，当前
  哪个结果值得作为前沿或比较锚点”；
- [跨领域迁移雷达](../transfer/README.md)回答“其他计算机领域的强机制，是否还
  有一个没有被自动驾驶研究直接覆盖、可以用最小实验判别的窄迁移接口”。

它们都不是排行榜聚合站，也不把“搜索没看到”改写成“确定没人做过”。

## 1. 为什么 SOTA 必须按协议拆开

同一个数据集上，下面任一项变化都可能让两个数字失去直接可比性：

- 数据版本、train/val/test split 或隐藏测试服务器；
- 相机、LiDAR、Radar、地图和历史帧等输入模态；
- 是否使用外部数据、预训练、模型集成或 test-time augmentation；
- 类别集合、空间范围、采样频率、未来时域和后处理；
- 指标实现、阈值、服务器版本、硬件、精度与时延测量方法。

因此机器索引 [index/sota.csv](../index/sota.csv) 的一行不是“一个领域的冠军”，
而是一个“任务 × 数据集 × split × 输入 × 外部数据 × 指标”的协议卡。页面只允许
四种证据身份：

1. `OfficialLeaderboardSnapshot`：官方动态榜单在指定日期的快照；
2. `PaperReportedFrontier`：正式论文在列明配置中的自报前沿；
3. `BenchmarkAnchor`：帮助理解当前协议与量级的代表性锚点；
4. `NoSingleLeaderboard`：方向内部没有一个诚实的统一排名值。

官方榜单提交不自动等于正式录用，论文自报数字不自动等于独立复现。生成页必须
同时显示快照日期、证据身份、协议、指标方向、数字来源和最大边界。

## 2. 13 类覆盖不等于强行给 13 个冠军

`index/taxonomy.json` 的 P01–P13 必须每天都有入口，但表示学习、开放世界、VLM、
世界模型、协同鲁棒性等方向往往同时包含多个互不等价的评价轴。此时雷达明确写
“无单一可比 SOTA”，列出当前 benchmark、指标菜单和近期正式论文锚点。这样既不
留下空白，也不会把 FID、mAP、VQA accuracy、带宽和闭环分数拼成一个虚假总榜。

当前首版优先纳入可以由官方 JSON 复查的 nuScenes 检测、跟踪、分割、全景和预测
快照，再用 CVF、ECVA、OpenReview、ICLR/NeurIPS proceedings 等正式入口补齐其他
方向。之后逐日扩展 Waymo、Argoverse 2、KITTI、SemanticKITTI、Occ3D、OpenOccupancy、
DAIR-V2X、OPV2V、nuScenes-R 等协议；扩展顺序由覆盖价值和官方可核验性决定，不用
聚合站数字凑数量。

## 3. 跨领域候选怎样进入雷达

候选源默认优先最近三年正式录用、在源任务上有强受控证据、作者官方源码和可解释
接口的方法。每天轮换检索以下来源域，长期形成覆盖矩阵：

- 2D 检测、分割、深度、匹配和高分辨率视觉；
- 视频理解、长序列建模、跟踪和时空记忆；
- 点云之外的 3D、图形学、神经渲染与几何学习；
- NLP、状态空间模型、图学习、稀疏专家和检索系统；
- 多模态、VFM/VLM、生成建模、世界模型和机器人学习；
- 编译、稀疏计算、压缩、推理系统和硬件协同设计。

热门仓库、论文周报、技术帖子和社区讨论只帮助发现候选和学习讲解顺序。论文身份、
机制、数字、局限与代码结论必须回到官方 proceedings、原论文、补充材料、作者项目
和固定 40 位 commit。

## 4. “还没人迁移”怎样做成可审查结论

每个准备高亮的迁移主张先拆成四个轴：

- **问题：** 原方法解决的瓶颈是否已在自动驾驶中被直接研究；
- **机制：** 核心算子、状态更新或训练信号是否已被迁入；
- **洞见：** 为什么有效的因果解释是否已经成为驾驶方法的设计依据；
- **场景：** 目标数据、模态、3D 表示、时序状态和评测协议是否已经覆盖。

随后至少执行三路不同检索式：问题词、机制词、同义词/邻域词。来源至少覆盖正式
proceedings、综合论文索引、arXiv/预印本入口和官方项目/源码；高亮项要精读并公开
最接近的 3–7 篇全文。检索判断只允许：

- `[已覆盖]`：直接组合已经存在，撤回机会；
- `[部分覆盖]`：只能保留精确的剩余差异；
- `[本次检索未找到直接覆盖]`：允许重点显示，但必须带日期、范围和最近工作；
- `[检索受阻]`：不能高亮，相关 PR 保留待查。

公开表述固定为“截至日期，在列明范围内本次未找到直接覆盖”。禁止“学界无人做过”、
“绝对首次”或任何没有检索范围的空白声明。高亮项最多 30 天重查一次；出现新会议
批次、预印本或直接碰撞时立即降级或撤下。

## 5. 候选评分与碰撞等级

迁移优先级满分 10 分：

- 源瓶颈和机制是否清楚：0–2；
- 跨任务接口是否具体：0–2；
- 模块级受控证据是否足够：0–2；
- 官方源码、固定版本和许可证是否完整：0–1.5；
- 自动驾驶中的剩余差异是否经碰撞检索保住：0–1.5；
- 最小实验、回滚与反证条件是否可执行：0–1。

碰撞等级沿用从低重合到直接覆盖的五级判断。公开页重点保留 Level 3 左右、仍有窄
机制差异的候选；Level 1–2 进入碰撞栏，防止未来重复包装。分数只排序下一步验证
价值，不是成功概率。

## 6. 每张迁移卡必须能被一个小实验推翻

机器索引 [index/transfer.csv](../index/transfer.csv) 保存检索与证据字段；
[中文教学层](../index/transfer_zh.json) 用同一个 `candidate_key` 保存 30 秒画面、接口、
实验与失效条件的移动端中文解释。生成器要求两边逐项一一对应，不能只更新其中一边。
每项必须同时公开：

- 源论文正式身份、源任务最强证据、官方仓库、固定 SHA 和许可证；
- 目标 P01–P13 方向、插入位置、输入输出、需要保留的基线接口；
- 三路检索式、带日期的检索来源、最近工作和碰撞等级；
- 最小接入实验、匹配的回滚基线、什么结果会推翻假设、最大失效条件；
- 有限检索的公开措辞边界和下次复核日期。

“在源领域达到 SOTA”只证明源协议中的效果，不能证明 2D→3D、图像→BEV 或语言
→感知迁移会成功。最小实验必须一次只改一个接口，匹配 backbone、预训练、数据、
训练预算和推理预算，并同时报告精度、效率、关键长尾类和稳定性。多个组件一起变化
时，整行提升不能归给候选模块。

## 7. 自动化与合并门槛

每天的论文精读、算法 Taste、SOTA 快照和迁移雷达使用同一个分支与 PR；当天已存在
完整精读和 Taste 时不再选第二篇。日更顺序是：

1. 刷新官方榜单和近期正式论文身份，保留旧快照的可追溯边界；
2. 轮换一个或多个来源域召回强算法，先查 `index/transfer.csv` 去重；
3. 对新候选执行三路碰撞检索，已覆盖项写入碰撞栏；
4. 固定源码 SHA、核验许可证，写最小实验和反证条件；
5. 生成两个移动端页面，运行全部仓库校验与公开 GitHub 页面检查。

本地与 CI 都运行：

```text
python scripts/rebuild_research_radar.py
python scripts/rebuild_research_radar.py --check
python scripts/rebuild_index.py --check
```

验证器会阻断：缺任一 P01–P13、混用未声明协议、官方榜单行没有榜单和值、正式论文
没有 proceedings、候选缺完整 SHA/许可证、少于三路检索、高亮项缺 3–7 篇最近
工作、检索受阻仍高亮、绝对空白措辞、复核时间超过 30 天以及生成页陈旧。

网络、官方榜单、检索源、CI 或公开页面检查失败时，保留可审查分支/PR并如实报告，
不能用缓存聚合榜或未经核验的“创新机会”强行合并。
