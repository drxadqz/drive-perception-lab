## 1. 看图：论文到底做了什么

### 1.1 先看范式差异：为什么不用多帧 queue

![ST-Occ Figure 2：递归、堆叠与统一时序建模三种范式的对比](../../assets/notes/2026-07-24-st-occ/fig-2-temporal-paradigms.png)

> **原图出处：** Leng et al., ICCV 2025, Figure 2，PDF p. 3 /
> proceedings p. 26571。[官方 PDF](https://openaccess.thecvf.com/content/ICCV2025/papers/Leng_Occupancy_Learning_with_Spatiotemporal_Memory_ICCV_2025_paper.pdf)。
> 仅作学术讲解所需的局部摘录，原图版权归原作者及其他权利人。

按这个顺序看：

1. **(a) Recurrent**：历史帧要逐次 warp 和融合，计算链随时间增长；
2. **(b) Stacked**：保留多帧 dense 3D feature，再一次性对齐和融合；
3. **(c) Unified**：只维护一份场景坐标中的统一 memory，当前帧读取局部、
   融合后再写回。

图右下角给出的相对量级是作者在该比较设置下的结果：统一方式记忆和计算均为
1.0×，recurrent 为 1.8× / 5.0×，stacked 为 2.0× / 2.0×。

**看完应能复述：** ST-Occ 的关键不是“再加一层 attention”，而是把历史状态
的地址从“第几帧”改成“场景中的哪个位置”。

**这张图没有证明：** 不同硬件、实现优化或任意序列长度下都会保持相同比例。

### 1.2 再看总体框架：memory 在哪里读、在哪里写

![ST-Occ Figure 3：从多视角图像到场景记忆与 Occupancy 预测的总体框架](../../assets/notes/2026-07-24-st-occ/fig-3-st-occ-overview.png)

> **原图出处：** Leng et al., ICCV 2025, Figure 3，PDF p. 5 /
> proceedings p. 26573。[官方 PDF](https://openaccess.thecvf.com/content/ICCV2025/papers/Leng_Occupancy_Learning_with_Spatiotemporal_Memory_ICCV_2025_paper.pdf)。
> 仅作学术讲解所需的局部摘录，原图版权归原作者及其他权利人。

图中的四个关键对象：

- $`\mathbf V_t`$：当前多视角图像经 Occupancy encoder 得到的局部 3D feature；
- $`\mathbf H_t`$：从场景 memory 中读出的历史信息；
- $`\widetilde{\mathbf V}_t`$：memory attention 融合后的时序 feature；
- $`\mathbf M_t`$：场景坐标中的持久 memory。

先沿下方主干看预测，再沿上方回路看状态：

```text
images
→ Occ encoder
→ current feature
→ memory attention 读取历史
→ fused feature
├─ Occ head → prediction
└─ alignment → 写回 scene memory
```

**最容易漏掉的一点：** prediction 是当前帧输出，memory write 是下一帧状态。
流式模型是否可靠，不只取决于当前预测，还取决于错误会不会被写入并继续传播。

### 1.3 最后看核心模块：flow 与 uncertainty 各做什么

![ST-Occ Figure 4：带动态与不确定性感知的 memory attention](../../assets/notes/2026-07-24-st-occ/fig-4-memory-attention.png)

> **原图出处：** Leng et al., ICCV 2025, Figure 4，PDF p. 5 /
> proceedings p. 26573。[官方 PDF](https://openaccess.thecvf.com/content/ICCV2025/papers/Leng_Occupancy_Learning_with_Spatiotemporal_Memory_ICCV_2025_paper.pdf)。
> 仅作学术讲解所需的局部摘录，原图版权归原作者及其他权利人。

从左到右看：

1. **Flow compensation** 移动历史 sampling points，处理动态物体的跨帧位移；
2. **Attention weights** 决定从哪些位置、以多大权重取当前与历史 feature；
3. **Uncertainty estimator** 读取历史类别分布、平均 log variance 和特征相似度；
4. **Uncertainty-aware fusion** 在当前分支和历史分支之间调节权重；
5. 输出 temporal-conditioned representation。

**看完应能复述：** flow 主要解决“去哪里取历史”，uncertainty gate 主要解决
“取到的历史应该信多少”。

## 2. 读公式：核心机制怎样表达

下面只收录理解方法和指标不可缺少的原文公式。公式根据作者 PDF 与 TeX
逐项核对；仅展开论文自定义宏、移除颜色命令并使用 GitHub 支持的排版，
不改变代数含义。

### 2.1 Unified memory 的读取与写回

**原文公式：** 论文 Eq. (5)–(6)，PDF p. 4 / proceedings p. 26572。

```math
\widetilde{F}^{\,t}_{\mathrm{unified}}
= \psi\!\left(F^t \mid \chi[M_t,T_t]\right)
```

```math
\chi[M_{t+1},T_t]
= \widetilde{F}^{\,t}_{\mathrm{unified}}
```

符号逐个看：

- $`F^t`$：当前帧的 Occupancy feature；
- $`M_t`$：时间 $`t`$ 的统一场景 memory；
- $`T_t`$：当前 ego pose，用来定位当前 RoI；
- $`\chi[\cdot]`$：在 memory 与当前 RoI 之间采样或写回；
- $`\psi`$：时序融合函数；
- $`\widetilde{F}^{\,t}_{\mathrm{unified}}`$：融合后的当前 feature。

**一句话理解：** 先按 pose 从一份场景 memory 中读取历史，再把融合结果写回
同一个物理区域；历史长度不再等于显式 feature queue 的长度。

**回到图：** Eq. (5) 对应 Figure 3 上方历史箭头进入 Memory Attention；
Eq. (6) 对应右侧 Alignment 后写回 memory 的箭头。

**落到源码：**
[`update_global`](https://github.com/matthew-leng/ST-Occ/blob/1633f62e2e6677a5fa474905977acfeca4e7819e/mmdet3d/models/stocc/detectors/stocc.py#L246-L380)
负责当前 RoI 与 scene grid 的映射和读取；
[`update_global_single`](https://github.com/matthew-leng/ST-Occ/blob/1633f62e2e6677a5fa474905977acfeca4e7819e/mmdet3d/models/stocc/detectors/stocc.py#L383-L549)
完成融合与写回。

**公式省略了什么：** 实现中的 memory 不只是一个 feature tensor，还包含
valid mask、count、类别分布、不确定性、flow 和 scene metadata。

### 2.2 Memory 中到底保存哪些属性

论文先定义每个 voxel 的 temporal attributes：
$`\mu_p \equiv \{\mathbf c_p,\delta_p,\mathbf f_p\}`$。

**原文公式：** 论文 Eq. (7)–(9)，PDF p. 4 / proceedings p. 26572。

```math
\chi[\mathbf M_{t+1}\langle\mathbf c\rangle,T_t]
=
\mathrm{softmax}\!\left(
\alpha\mathbf c_t
+(1-\alpha)\chi[\mathbf M_t\langle\mathbf c\rangle,T_t]
\right)
```

```math
\chi[\mathbf M_{t+1}\langle\delta\rangle,T_t]=\delta_t,
\qquad
\chi[\mathbf M_{t+1}\langle\mathbf f\rangle,T_t]=\mathbf f_t
```

```math
\chi[\mathbf M_{t+1}\langle\mathbf V\rangle,T_t]
=\widetilde{\mathbf V}_t
```

- $`\mathbf c`$：历史类别 activation；
- $`\delta`$：跨类别平均后的 log variance；
- $`\mathbf f`$：俯视平面中的 Occupancy flow；
- $`\mathbf V`$：历史 Occupancy representation；
- $`\alpha`$：类别 activation 的衰减系数，论文实现设置为 0.5。

**一句话理解：** ST-Occ 写回的不只是“融合 feature”，还同步更新类别、
不确定性与运动线索；这也是为什么实际 state 比 Figure 3 中的一块 memory 更复杂。

**落到源码：**
[`register_scene_buffer`](https://github.com/matthew-leng/ST-Occ/blob/1633f62e2e6677a5fa474905977acfeca4e7819e/mmdet3d/models/stocc/detectors/stocc.py#L212-L244)
分配各类 scene buffer，
[`forward_train`](https://github.com/matthew-leng/ST-Occ/blob/1633f62e2e6677a5fa474905977acfeca4e7819e/mmdet3d/models/stocc/detectors/stocc.py#L733-L764)
包含类别分布的递推更新。

> [!IMPORTANT]
> **[源码] 论文变量与发布代码变量不能直接画等号。** 论文中的 $`\delta`$
> 是跨类别平均的 log variance；发布代码先对 raw head 输出做 `softplus`，
> 再取指数得到 variance，跨类别求均值后还会在每个样本的空间范围内做
> min–max normalization，才写入 `global_au`。进入 uncertainty estimator
> 时又使用 `1 - global_au`。因此 `global_au` 不是论文 $`\delta`$ 的逐值实现。
> 见
> [`aggregate_uncertainty` 与 uncertainty head](https://github.com/matthew-leng/ST-Occ/blob/1633f62e2e6677a5fa474905977acfeca4e7819e/mmdet3d/models/stocc/heads/occupancy_head_w_au.py#L222-L296)
> 及
> [`UncertaintyEstimator_w_feature_au`](https://github.com/matthew-leng/ST-Occ/blob/1633f62e2e6677a5fa474905977acfeca4e7819e/mmdet3d/models/stocc/modules/uncertainty.py#L29-L46)。

### 2.3 Uncertainty 与 flow 怎样进入 attention

**原文公式：** 论文 Eq. (10)–(12)，PDF p. 5 / proceedings p. 26573。

```math
\widetilde{\mathbf V}_t
=
\psi(\mathbf V_t\mid\mathbf H_t)
=
\psi\!\left(\mathbf V_t\mid\chi[\mathbf M_t,T_t]\right)
```

```math
u=\mathrm{MLP}(\mathbf c,\delta,\varepsilon)
```

```math
(1-u)\,
\mathrm{DA}(\mathbf V_{t_p},p+\mathbf f,\mathbf V_t)
+
u\,
\mathrm{DA}\!\left(
\mathbf V_{t_p},p+\mathbf f,\chi[\mathbf M_t,T_t]
\right)
```

- $`\varepsilon`$：当前与历史 representation 在同一物理位置的 cosine similarity；
- $`u`$：MLP 预测的融合权重；按 Eq. (12)，值越大时历史 memory 分支权重越高；
- $`p+\mathbf f`$：用 Occupancy flow 调整后的 sampling location；
- $`\mathrm{DA}`$：deformable attention。

**一句话理解：** flow 改变采样位置，$`u`$ 改变当前与历史两条 attention
分支的混合比例。

> [!WARNING]
> **论文—源码差异（必须分开理解）：** **[论文]** Eq. (12) 是
> `current × (1-u) + history × u`，所以论文符号 $`u`$ 越大，历史分支越重。
> **[源码]** 发布仓库默认的 implicit 路径先令 `prev_weights = 1-u`，
> 随后执行 `history × prev_weights + current × (1-prev_weights)`，代入后是
> `history × (1-u) + current × u`，与论文中 $`u`$ 的分支语义相反。
> 这可能是变量采用了互补语义，也可能需要作者澄清；**[未核验]** 本仓库尚未
> 加载官方 checkpoint 做数值追踪，因此这里只报告可读源码事实，不把它直接
> 定性为实现错误。默认设置见
> [`stocc-r50-256x704-36e.py` L125–145](https://github.com/matthew-leng/ST-Occ/blob/1633f62e2e6677a5fa474905977acfeca4e7819e/occupancy_configs/st_occ/stocc-r50-256x704-36e.py#L125-L145)，
> 混合路径见
> [`encoder.py` L347–365](https://github.com/matthew-leng/ST-Occ/blob/1633f62e2e6677a5fa474905977acfeca4e7819e/mmdet3d/models/stocc/temporal/encoder.py#L347-L365)
> 与
> [`temporal_self_attention.py` L311–319](https://github.com/matthew-leng/ST-Occ/blob/1633f62e2e6677a5fa474905977acfeca4e7819e/mmdet3d/models/stocc/temporal/temporal_self_attention.py#L311-L319)。

**回到图：** Figure 4 左侧的 Flow Compensation 对应 $`p+\mathbf f`$；
紫色 Uncertainty Map 对应 $`u`$；Current/Historical Feature 两支对应
Eq. (12) 的两项。

**落到源码：**
[`VoxelFormerEncoder.forward`](https://github.com/matthew-leng/ST-Occ/blob/1633f62e2e6677a5fa474905977acfeca4e7819e/mmdet3d/models/stocc/temporal/encoder.py#L229-L378)

[`VoxelTemporalSelfAttention_w_Uncertainty`](https://github.com/matthew-leng/ST-Occ/blob/1633f62e2e6677a5fa474905977acfeca4e7819e/mmdet3d/models/stocc/temporal/temporal_self_attention.py#L142-L331)

[`UncertaintyEstimator_w_feature_au`](https://github.com/matthew-leng/ST-Occ/blob/1633f62e2e6677a5fa474905977acfeca4e7819e/mmdet3d/models/stocc/modules/uncertainty.py#L7-L46)

### 2.4 mSTCV 到底测了什么

论文把历史 prediction $`\mathbf P`$ 与 ground truth $`\mathbf G`$ 写入场景 memory：

**原文公式：** 论文 Eq. (13)–(15)，PDF p. 5 / proceedings p. 26573。

```math
\chi[\mathbf M_{t+1}\langle\mathbf P\rangle,T_t]=\mathbf P_t,
\qquad
\chi[\mathbf M_{t+1}\langle\mathbf G\rangle,T_t]=\mathbf G_t
```

```math
\mathrm{STCV}_t
=
\frac{
\sum \mathbf 1\!\left[
\left(\chi[\mathbf M_t\langle\mathbf P\rangle,T_t]\ne\mathbf P_t\right)
\land
\left(\chi[\mathbf M_t\langle\mathbf P\rangle,T_t]\ne\mathrm{Free}\right)
\right]
}{
\sum \mathbf 1[\mathbf P_t\ne\mathrm{Free}]
}
```

```math
\mathrm{mSTCV}
=
\frac{1}{T}\sum_{t}^{T}\mathrm{STCV}_t
```

这里用 $`\mathbf 1`$ 表示 indicator；原论文使用的黑板粗体 1 在此做了
GitHub 兼容的排版归一化。

**一句话理解：** 按论文公式，STCV 统计同一场景位置上的非 free voxel 在
memory 中最近一次已写入的历史 prediction 与当前 prediction 之间发生类别
变化的比例，再对帧求平均；它不保证比较对象一定来自紧邻上一帧。

**关键边界：** 低 mSTCV 说明 flicker 更少，但一个稳定的错误也可能得到低值；
因此它必须与 mIoU、校准或错误持续时间共同解释。

> [!IMPORTANT]
> **[源码] 发布评测口径不是对 Eq. (14) 的逐字计算。** 模型侧在场景对齐
> 位置分别累计 prediction flicker 与 GT flicker；`condition_mask` 接受
> $`0<\mathrm{GT}\le18`$，若提供 `gt_speed_map`，还排除速度大于 0.5 的
> dynamic voxel。数据集评测最终使用
> `(prediction flicker - GT flicker) / GT non-free voxel count`，
> 再对帧平均。也就是说，Table 2 的 12.18% → 8.68% 应理解为作者发布
> 实现口径下的结果，而不是只按上面 Eq. (14) 即可复算的 prediction-only 指标。
> 见
> [`stocc.py` L850–969](https://github.com/matthew-leng/ST-Occ/blob/1633f62e2e6677a5fa474905977acfeca4e7819e/mmdet3d/models/stocc/detectors/stocc.py#L850-L969)
> 与
> [`nuscenes_dataset.py` L670–714](https://github.com/matthew-leng/ST-Occ/blob/1633f62e2e6677a5fa474905977acfeca4e7819e/mmdet3d/datasets/nuscenes_dataset.py#L670-L714)。
>
> **[未核验] 复现时要加一个 smoke test：** 发布代码用 `previous != 0`
> 判断历史是否初始化，同时 prediction `argmax` 的合法类别索引也包含 0。
> 在真实 checkpoint 与序列上追踪前，只能记为潜在哨兵冲突，不能称为已证实 bug。

### 2.5 Uncertainty 怎样进入训练损失

**原文公式：** 论文 Eq. (16)–(18)，PDF p. 6 / proceedings p. 26574。

```math
\mathcal L_{\mathrm{occ}}
=
\mathcal L_{\mathrm{fl}}
+\mathcal L_{\mathrm{ls}}
+\mathcal L_{\mathrm{scal}}^{\mathrm{geo}}
+\mathcal L_{\mathrm{scal}}^{\mathrm{sem}}
+\mathcal L_{\mathrm d}
```

```math
\mathcal L_{\mathrm{nll}}
=
\sum_i \frac{1}{2}
\left(
\exp(-s_i)\lVert y_i-\widehat y_i\rVert^2+s_i
\right)
```

```math
\mathcal L
=
\mathcal L_{\mathrm{occ}}
+\mathcal L_{\mathrm{nll}}
+\mathcal L_{\mathrm{of}}
```

$`\mathcal L_{\mathrm{fl}}`$、$`\mathcal L_{\mathrm{ls}}`$、
$`\mathcal L_{\mathrm{scal}}^{\mathrm{geo}}`$、
$`\mathcal L_{\mathrm{scal}}^{\mathrm{sem}}`$ 与 $`\mathcal L_{\mathrm d}`$
分别是 focal、Lovász-softmax、geometric scaling、semantic scaling 与
depth loss。$`s_i`$ 是预测的 log variance，$`\mathcal L_{\mathrm{of}}`$
是 Occupancy flow 的 L1 loss。按论文 Eq. (17)，较大的方差可降低高残差样本
的权重，而 $`s_i`$ 项又惩罚无约束地放大方差。

**[源码] 发布代码采用了相关但不相同的分类版本。** Head 先构造
$`v_{i,y_i}=\exp(\mathrm{softplus}(r_{i,y_i}))`$，再选出正确类别概率
$`p_{i,y_i}`$ 与该类别 variance。由代码逐行整理得到：

**[源码] 由实现整理的等价结构（不是论文原文公式）：**

```math
\mathcal L_{\mathrm{code}}
=
\mathrm{mean}_i\left[
\frac{-\log p_{i,y_i}}{2v_{i,y_i}}
+\frac{1}{2}\log v_{i,y_i}
\right]
```

所以论文 Eq. (17) 的平方残差被发布实现中的正确类别负对数概率替代；
两者有相同的“数据项按方差降权 + 对数方差正则”结构，但不能称为逐字实现。
见
[`variance 构造`](https://github.com/matthew-leng/ST-Occ/blob/1633f62e2e6677a5fa474905977acfeca4e7819e/mmdet3d/models/stocc/heads/occupancy_head_w_au.py#L289-L296)、
[`nll_loss_with_uncertainty`](https://github.com/matthew-leng/ST-Occ/blob/1633f62e2e6677a5fa474905977acfeca4e7819e/mmdet3d/models/stocc/heads/occupancy_head_w_au.py#L23-L69)
和
[`loss 调用点`](https://github.com/matthew-leng/ST-Occ/blob/1633f62e2e6677a5fa474905977acfeca4e7819e/mmdet3d/models/stocc/heads/occupancy_head_w_au.py#L374-L385)。

### 3.1 主结果：是否优于直接 baseline

三个必须看的对照：

1. **ST-Occ vs temporal FB-OCC：** 42.13 vs 39.11 mIoU，绝对提高 3.02；

**[判断] 仍需保留的边界：** 所有对照仍在同一个数据域和任务设置中；
没有跨域、恶劣天气、相机故障、随机种子方差或置信区间。

### 3.3 组件消融：收益来自 memory，还是 flow / uncertainty

![ST-Occ Table 4：memory attention、dynamics 与 uncertainty 的组件消融](../../assets/notes/2026-07-24-st-occ/table-4-component-ablation.png)

> **原图出处：** Leng et al., ICCV 2025, Table 4，PDF p. 8 /
> proceedings p. 26576。[官方 PDF](https://openaccess.thecvf.com/content/ICCV2025/papers/Leng_Occupancy_Learning_with_Spatiotemporal_Memory_ICCV_2025_paper.pdf)。
> 此处截取原表左侧设置、mIoU 与少量相邻类别列；完整类别结果见官方 PDF。
> 原图版权归原作者及其他权利人。

从第一列 mIoU 读：

- No Temporal → Mem. Attn.：37.39 → 41.17，增加 3.78；
- Mem. Attn. → +Dynamics：41.17 → 41.73，增加 0.56；
- Mem. Attn. → +Uncertainty：41.17 → 41.85，增加 0.68；
- Mem. Attn. → 两者都加：41.17 → 42.13，增加 0.96。

**[论文] 最有力的因果线索：** 最大增益来自 memory attention 本身，
dynamics 与 uncertainty 在其上提供较小、方向一致的补充收益。

**[判断] 最大疑点：** 0.28–0.68 量级的组件差异没有 seed 方差，不能判断
小增益是否稳定；类别级加粗也不等于经过显著性检验。

### 结果部分的最终判断

- **Strong：** 标准 Occ3D 设置中的主结果、no-temporal 对照和 memory
  attention 主效应；
- **Medium：** dynamics / uncertainty 的互补、mSTCV 与效率；
- **Weak / 未覆盖：** 跨域、传感器故障、故障后恢复、校准、
  状态污染与严格可复现性。

## 4. 对源码：公式如何落地

固定版本：
[`1633f62e2e6677a5fa474905977acfeca4e7819e`](https://github.com/matthew-leng/ST-Occ/commit/1633f62e2e6677a5fa474905977acfeca4e7819e)。

先按与图和公式相同的顺序读：

```text
多相机图像
→ 当前 voxel feature
→ scene buffer 读取当前 RoI
→ flow-conditioned temporal attention
→ uncertainty-aware fusion
→ scene buffer 写回
→ occupancy / uncertainty / flow heads
```

### 4.1 读写场景记忆：`update_global` / `update_global_single`

- **论文对应：** Eq. (5)–(9)；
- **[源码] 实际行为：** `update_global` 计算 ego voxel 在全局 grid 中的位置，
  经 round、clamp 和 `grid_sample` 读取历史；`update_global_single`
  调用 temporal encoder 后用 indexed write 更新相应 scene region；
- **需要留意：** 离散化、重复 index、scene reset 和 batch-slot 隔离都会改变
  stateful inference；
- [打开 `update_global`](https://github.com/matthew-leng/ST-Occ/blob/1633f62e2e6677a5fa474905977acfeca4e7819e/mmdet3d/models/stocc/detectors/stocc.py#L246-L380) ·
  [打开 `update_global_single`](https://github.com/matthew-leng/ST-Occ/blob/1633f62e2e6677a5fa474905977acfeca4e7819e/mmdet3d/models/stocc/detectors/stocc.py#L383-L549)

### 4.2 Flow 与 deformable attention：`VoxelFormerEncoder`

- **论文对应：** Figure 4 与 Eq. (12) 的 $`p+\mathbf f`$；
- **[源码] 实际行为：** predicted 或 GT flow 改变历史 sampling position，
  temporal attention 再预测内容相关 offsets 和 weights；
- **需要留意：** motion error 不只影响当前帧，还可能改变后续 memory 的读取路径；
- [打开 temporal encoder](https://github.com/matthew-leng/ST-Occ/blob/1633f62e2e6677a5fa474905977acfeca4e7819e/mmdet3d/models/stocc/temporal/encoder.py#L229-L378) ·
  [打开 temporal attention](https://github.com/matthew-leng/ST-Occ/blob/1633f62e2e6677a5fa474905977acfeca4e7819e/mmdet3d/models/stocc/temporal/temporal_self_attention.py#L142-L331)

### 4.3 Uncertainty gate：`UncertaintyEstimator_w_feature_au`

- **论文对应：** Eq. (11)–(12)；
- **[源码] 实际行为：** gate 使用 observation、distance、类别分布、
  cosine similarity 与 aleatoric uncertainty；默认 implicit 路径最终混合成
  `history × (1-u) + current × u`；
- **需要留意：** 这与论文 Eq. (12) 对 $`u`$ 的分支语义相反，且是内容相关
  的非线性递推；必须按上文“论文—源码差异”理解，不能把公式和代码无缝等同；
- [打开 uncertainty estimator](https://github.com/matthew-leng/ST-Occ/blob/1633f62e2e6677a5fa474905977acfeca4e7819e/mmdet3d/models/stocc/modules/uncertainty.py#L7-L46) ·
  [打开 encoder gate](https://github.com/matthew-leng/ST-Occ/blob/1633f62e2e6677a5fa474905977acfeca4e7819e/mmdet3d/models/stocc/temporal/encoder.py#L347-L365) ·
  [打开 attention mix](https://github.com/matthew-leng/ST-Occ/blob/1633f62e2e6677a5fa474905977acfeca4e7819e/mmdet3d/models/stocc/temporal/temporal_self_attention.py#L311-L319)

### 4.4 Uncertainty loss：论文式与代码式

- **论文对应：** Eq. (16)–(18)；
- **[源码] 实际行为：** 对正确类别概率使用 variance-weighted negative
  log-likelihood，并对 variance 加 log penalty；

### 4.6 状态规模为什么会变大

**[判断] 以下是本笔记的量级换算，不是论文原始公式：**

```math
\begin{aligned}
100\times100\times8\times80
&=6.4\times10^6\ \text{values},\\
\frac{6.4\times10^6\times4\ \text{bytes}}{2^{20}}
&\approx24.4\ \text{MiB}.
\end{aligned}
```

补充材料给出的平均空间增长为
$`\Delta_{\mathrm{mean}}=3.25`$。论文的 101 个 state channels 已包含
80 feature、18 class activation、2 flow 和 1 uncertainty channel。若只为
理解量级而按其口径粗估：

**[判断] 量级换算（不是论文原始公式）：**

```math
24.4\ \mathrm{MiB}
\times\frac{101}{80}
\times(1+3.25)
\approx131\ \mathrm{MiB}.
```

真实工作集还包含 count、validity、坐标与评测 buffers；这个 131 MiB 是笔记
估算，不是作者报告的完整峰值，也没有把 flow 重复计算。

**[源码] 可见的持久状态**

- `global_feats`：scene-sized 80-channel feature；
- `global_valid_masks`、`global_vis_cnt`：validity 与 observation count；

- 确定性：5D `grid_sample`、duplicate index、dropout、scene reset；
- 训练/测试差异：测试把 predicted flow 存入名为 `gt_flow` 的变量供下一帧使用；

## 5. 记结论：贡献、边界与开放问题

### 学完必须记住的三点

1. **[论文] 方法核心：** scene-centered unified memory 把长历史从显式
   dense frame queue 变成一份按场景位置寻址的递推状态。
2. **[论文] 最强证据：** Occ3D 主结果、no-temporal / temporal 对照、
   mSTCV、效率和消融共同说明该设计在作者设置中有效。
3. **[判断] 最大缺口：** 除了跨域、异常输入与状态恢复未验证，发布源码在
   Eq. (12) 权重语义、Eq. (17) 损失实现和 mSTCV 评测口径上都不是论文公式
   的逐字对应；复现必须同时报告“论文定义”和“代码口径”。

### 论文目前没有回答的问题

#### 1. 错误历史会不会形成故障后效

- **已观察事实：** 作者展示 history length 增长带来的正常条件收益；
- **未回答：** 相机冻结、错位或噪声结束后，memory 是否继续保留错误；
- **最小测试：** 在固定时段注入异常，异常结束后同时测 mIoU、mSTCV、
  state divergence 与恢复时间。

#### 2. 时间一致性是否掩盖稳定错误

- **已观察事实：** mSTCV 从 12.18% 降到 8.68%；
- **未回答：** 低 flicker 是否可能来自“持续预测成同一个错误类别”；
- **最小测试：** 把 voxel 分成 correct-stable、wrong-stable、correct-flicker、
  wrong-flicker 四类并报告持续长度。

#### 3. Motion 的 train/test gap 会不会递推放大

- **[源码] 已观察事实：** 训练与测试的 flow 来源不同；
- **未回答：** predicted flow 的误差是否通过后续 sampling 累积；
- **最小测试：** GT-flow、predicted-flow、no-flow 三组按序列长度画性能与
  state drift 曲线。

这些是待检索和待实验的问题，不是已经成立的新颖性结论。跨论文状态见
[公开研究缺口雷达](../../index/open_questions.md)。
