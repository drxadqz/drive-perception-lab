## 0. 阅读起点：术语先导与摘要完整翻译

### 0.1 首次术语解释

**术语覆盖声明：** 摘要里的核心专业名词先在这里解释；摘要之后第一次出现的
新术语仍在正文首次出现处解释。全文固定使用同一中文名、英文名、缩写和符号，
不在“占据表征”“占用表示”等译法之间来回切换。

- **三维占据（3D occupancy）**：把车辆周围空间切成规则三维格子，并预测
  每个格子是否被占据以及所属语义类别；它比只画检测框更细粒度。
- **体素（Voxel）**：三维网格中的最小单元，可以把它理解成二维像素在三维
  空间中的对应物。
- **占据表征（Occupancy representation）**：模型内部编码各空间位置的
  占据状态、类别和特征的信息表示。
- **场景级占据表征（Scene-level occupancy representation）**：在统一场景
  坐标中组织、可跨车辆运动持续聚合的占据表征，而不是只描述当前自车坐标范围。
- **时空记忆（Spatiotemporal memory）**：ST-Occ 按场景位置维护的持续状态，
  用来保存历史占据特征、类别、不确定性和运动信息。
- **记忆注意力（Memory attention）**：以当前体素特征为查询，从时空记忆
  读取并融合相关历史信息的注意力模块。
- **统一时序建模（Unified temporal modeling）**：本文提出的时序融合范式；
  它不按帧保留多份稠密历史，而是持续读写一份场景坐标记忆。
- **时序一致性（Temporal consistency）**：空间对齐后，同一真实位置跨帧
  预测保持稳定的程度；稳定不自动等于正确，必须与精度指标一起看。
- **占据流（Occupancy Flow）**：描述动态体素跨时间发生空间位移的运动量；
  本文用 nuScenes 实例标注监督一个显式估计器来预测它。
- **不确定性感知（Uncertainty awareness）**：估计体素证据的可靠程度，并
  据此调节当前信息与历史信息的融合比例。
- **动态感知（Dynamic awareness）**：识别并补偿物体自身运动造成的位置
  变化；它不同于由自车运动引起的坐标变化。
- **平均交并比（mean Intersection-over-Union, mIoU）**：先计算每类预测与
  真值的交集除以并集，再跨类别平均；越高越好，但不等于总体准确率。
- **平均时空分类变异度（mean Spatiotemporal Classification Variability,
  mSTCV）**：作者提出的跨帧分类变化指标；越低表示作者口径下闪烁更少，
  但不能单独证明预测更正确。

## 1. 看图：论文到底做了什么

### 1.1 先搭一座“积木城市”：Occupancy 是什么

想象桌面上有一座由小积木搭成的城市。每一块小立方体都对应现实空间中的
一小块区域：有的格子是道路，有的是汽车，有的是行人、建筑，也有的是空地。
论文把这种三维小格称为 **voxel**。

自动驾驶的 **3D semantic occupancy** 任务，就是让模型给车辆周围的每个
voxel 判断语义类别。它与普通 3D 检测框的区别在于：

- 检测框像“用一个长方体圈住一辆车”；
- occupancy 像“逐格涂色”，可以描述道路、植被、建筑和不规则障碍物；
- occupancy 有高度维，因此不是一张普通俯视图，而像一摞叠起来的棋盘。

贯穿全文的玩具场景是这样的：

```text
时刻 t-1：本车在路口左侧，红色汽车位于 A，大卡车没有遮挡。
时刻 t  ：本车向前移动，红色汽车从 A 开到 B，大卡车挡住右侧相机。
时刻 t+1：遮挡消失，本车需要判断旧记忆还能不能信。
```

这里有三个容易混淆的问题：

1. **本车在动。** 同一栋建筑在本车坐标中看起来会移动，ego pose alignment
   要把它重新放回统一场景坐标；
2. **物体在动。** 红色汽车真的从 A 到了 B，Occupancy flow 要估计它的位移；
3. **可见性和证据质量在变。** 遮挡或模糊会让新旧信息可靠程度不同，
   uncertainty-aware fusion 要决定应该更信哪一边。

> [!IMPORTANT]
> Ego pose 解决“地图坐标变了”，flow 解决“物体自己动了”，uncertainty
> 解决“新旧证据该信多少”。这三件事不是同一个对齐问题。

### 1.2 三种保存历史的方法：重画地图、保存相册、维护城市地图

![ST-Occ Figure 2：递归、堆叠与统一时序建模三种范式的对比](../../assets/notes/2026-07-24-st-occ/fig-2-temporal-paradigms.png)

> **原图出处：** Leng et al., ICCV 2025, Figure 2，PDF p. 3 /
> proceedings p. 26571。[官方 PDF](https://openaccess.thecvf.com/content/ICCV2025/papers/Leng_Occupancy_Learning_with_Spatiotemporal_Memory_ICCV_2025_paper.pdf)。
> 仅作学术讲解所需的局部摘录，原图版权归原作者及其他权利人。

按“怎样保存一本行车记录”来读这张图：

1. **(a) Recurrent：不断重画上一版地图。** 每到新时刻，都把上一版 feature
   warp 到当前坐标，再融合新观察。信息经过的连续变换会随时间增加；
2. **(b) Stacked：保存多本旧相册。** 把多帧 dense 3D feature 都留下，
   需要时统一对齐和融合；旧信息少经历递归改写，但要同时保存多份大张量；
3. **(c) Unified：只维护一张按地点编号的城市地图。** 当前车辆按 pose
   读取附近区域，融合后再把新理解写回同一个场景位置。

作者在 Figure 2 的比较设置中给出相对量级：unified 的记忆和计算均记为
1.0×，recurrent 为 1.8× / 5.0×，stacked 为 2.0× / 2.0×。

**初学者版结论：** ST-Occ 不需要为每个历史时刻保存一整套“城市副本”，
而是对一张城市地图做局部读取和局部更新。

**专业版结论：** 它把时序状态的主索引从 frame index 改成 scene coordinate，
用 scene-centered persistent memory 取代显式 dense feature queue。

**这张图没有证明：** 所有 recurrent 或 stacked 模型、任意历史长度和任意
硬件都会保持上述固定比例；这些是作者实现和比较设置中的结果。

### 1.3 一帧怎样流过 ST-Occ：先看当前预测，再看下一帧状态

![ST-Occ Figure 3：从多视角图像到场景记忆与 Occupancy 预测的总体框架](../../assets/notes/2026-07-24-st-occ/fig-3-st-occ-overview.png)

> **原图出处：** Leng et al., ICCV 2025, Figure 3，PDF p. 5 /
> proceedings p. 26573。[官方 PDF](https://openaccess.thecvf.com/content/ICCV2025/papers/Leng_Occupancy_Learning_with_Spatiotemporal_Memory_ICCV_2025_paper.pdf)。
> 仅作学术讲解所需的局部摘录，原图版权归原作者及其他权利人。

先沿图下方看“现在预测什么”：

```text
多视角图像
→ Occupancy encoder
→ 当前 3D feature V_t
→ Memory Attention 融合历史 H_t
→ 融合 feature V_tilde_t
→ Occupancy head
→ 当前预测
```

再沿图上方看“下一帧会记得什么”：

```text
场景 memory M_t
→ 按当前 ego pose 读取局部 H_t
→ 与当前 V_t 融合
→ Alignment
→ 把融合结果写回 M_(t+1)
```

四个对象可以这样记：

- ***V***<sub>*t*</sub>：本帧相机产生的当前 3D feature；
- ***H***<sub>*t*</sub>：从场景 memory 中读取的历史 feature；
- ***Ṽ***<sub>*t*</sub>：当前与历史融合后的 feature；
- ***M***<sub>*t*</sub>：在 scene coordinate 中持续存在的 memory。

> [!WARNING]
> 对普通单帧模型，一次错误主要影响当前输出；对状态化模型，错误还可能被
> 写回 memory，继而改变未来的读取、attention 和输出。这个结构允许“故障
> 后效”，但论文没有做相机故障恢复实验，所以这里只把它列为需要验证的问题，
> 不把长期污染写成已经证实的事实。

### 1.4 Flow 与 uncertainty：一个决定“去哪里找”，一个决定“信多少”

![ST-Occ Figure 4：带动态与不确定性感知的 memory attention](../../assets/notes/2026-07-24-st-occ/fig-4-memory-attention.png)

> **原图出处：** Leng et al., ICCV 2025, Figure 4，PDF p. 5 /
> proceedings p. 26573。[官方 PDF](https://openaccess.thecvf.com/content/ICCV2025/papers/Leng_Occupancy_Learning_with_Spatiotemporal_Memory_ICCV_2025_paper.pdf)。
> 仅作学术讲解所需的局部摘录，原图版权归原作者及其他权利人。

回到红色玩具车：上一帧它在 A，这一帧到了 B。若模型仍从 A 读取历史，
旧位置会留下“幽灵汽车”。Figure 4 从左到右做五件事：

1. **Flow compensation** 用预测 flow 调整历史 sampling position；
2. **Deformable attention** 在修正位置附近学习 offsets 和 weights；
3. **Uncertainty estimator** 读取类别状态、不确定性和新旧特征相似度；
4. **Gate** 调节当前分支与历史分支的混合比例；
5. 输出 temporal-conditioned representation。

**一句话记忆：** pose 先把街区找对，flow 再追踪街区里的移动物体，
uncertainty gate 最后决定旧地图值得信到什么程度。

### 1.5 整体算法架构与创新设计

这一节把前面的三张图连成一条完整设计因果链。最重要的区分是：ResNet‑50、
FB‑OCC 的单帧 Occupancy encoder 和常规 Occupancy head 不是 ST‑Occ 的原创；
ST‑Occ 真正改变的是二者之间怎样保存、读取和融合长期历史。

**原方法瓶颈：** **[论文]** 稠密 3D voxel feature 很大；recurrent 方法会让
旧信息反复 warp 和改写，stacked 方法又要保留多份历史张量。遮挡会把不可靠
特征带进融合，动态物体还会在旧位置产生错位。因此作者把挑战归纳为效率、
不确定性和动态性三类。来源：论文 §1 / Figure 2，PDF p. 1–3。

**主干网络与基线：** **[论文/源码]** 默认实验以去掉原 temporal fusion 的
FB‑OCC 为直接基线：六路 256×704 图像先经过 ResNet‑50、CustomFPN 和
CM_DepthNet，再由 LSS forward projection 与 BEVFormer backward projection
生成 3D 特征，随后经过 3D ResNet‑18 / FPN 和 Occupancy head。论文公开的
当前占据表征 ***V***<sub>*t*</sub> 尺寸为 100×100×8×80；ViewFormer 只用于
验证时序模块可迁移，并非默认基线框架或实验主线。这里的 CustomFPN 是把
ResNet 多尺度图像特征整理到统一通道数的特征金字塔；CM_DepthNet 为每个
图像位置预测深度分布与上下文特征；LSS forward projection 按深度概率把
图像特征“抬升”进三维网格，BEVFormer-style backward projection 再让三维
query 回到图像特征中取证；3D ResNet‑18 / FPN3D 则在体素空间继续提炼并融合
多尺度特征。来源：论文 §5.2，PDF p. 6；
[固定 SHA 配置](https://github.com/matthew-leng/ST-Occ/blob/1633f62e2e6677a5fa474905977acfeca4e7819e/occupancy_configs/st_occ/stocc-r50-256x704-36e.py#L180-L311)。

**继承与新增边界：** **[论文/源码]** 继承部分负责“把当前多相机图像变成
当前 3D voxel feature，并从 feature 产生 Occupancy”；ST‑Occ 新增或改写的
部分是 scene-centered spatiotemporal memory、三层 temporal self-attention、
flow compensation、uncertainty gate，以及 class / log-variance / flow 三条
输出分支和 mSTCV 评测。论文比较时移除了 FB‑OCC 原 temporal module，其余设置
保持一致。来源：论文 §4 与 §5.2，PDF p. 3–6；
[固定 SHA detector](https://github.com/matthew-leng/ST-Occ/blob/1633f62e2e6677a5fa474905977acfeca4e7819e/mmdet3d/models/stocc/detectors/stocc.py#L95-L164)。

**端到端信息流：** **[论文/源码]** 六路图像 ***I***<sub>*t*</sub> →
ResNet‑50 / CustomFPN → CM_DepthNet 产生 context feature 与 depth
distribution → LSS 3D forward projection 加 BEVFormer-style backward
projection → 当前粗粒度体素特征 ***V***<sub>*t*</sub> → 按 ego pose 从
***M***<sub>*t*</sub> 读取 ***H***<sub>*t*</sub> → flow 修正历史采样位置 →
三层 uncertainty-aware temporal self-attention 得到
***Ṽ***<sub>*t*</sub> → 一路对齐写回 ***M***<sub>*t*+1</sub>，另一路经过
3D ResNet‑18 / FPN3D 和上采样后进入 Occupancy / log-variance / flow heads。
来源：论文 Figure 3–4 / §4，PDF p. 5；
[固定 SHA detector](https://github.com/matthew-leng/ST-Occ/blob/1633f62e2e6677a5fa474905977acfeca4e7819e/mmdet3d/models/stocc/detectors/stocc.py#L551-L595)。

**总体训练方式：** **[论文/源码]** 作者以学习率 2×10<sup>−4</sup> 训练，
论文写 26 epochs，并在前 3 epochs 关闭 temporal modeling，让单帧分支先
稳定。主损失由 Occupancy 分类/结构损失、uncertainty NLL、flow L1 和
图像到体素前端的 depth supervision 组成；论文把 flow 真值概括为实例框
跨时间位移，代码则栅格化 annotation velocity。固定配置使用 AdamW、fp16
和 36e 上限，而公开 checkpoint 实际呈现 28e 口径，三者不能静默混写。
来源：论文 §4.5 与 §5.2，PDF p. 5–6；
[固定 SHA 配置](https://github.com/matthew-leng/ST-Occ/blob/1633f62e2e6677a5fa474905977acfeca4e7819e/occupancy_configs/st_occ/stocc-r50-256x704-36e.py#L302-L310)。

下面四张竖向卡分别回答“模块放在哪里、吃什么、做什么、为什么这样做、怎样
训练、证据能支持到哪里”。**可变形注意力（deformable attention）** 指只在
少量可学习采样点上聚合特征，而不是在完整 3D 网格上做全连接注意力。

#### 创新模块 1：Scene-centered Spatiotemporal Memory

**位置与接口：** 它位于单帧 Occupancy encoder 与 memory attention / 状态
写回路径之间，是跨帧长期状态，而不是额外保存的一组历史帧文件。

**输入：** 当前 3D 特征 ***V***<sub>*t*</sub>、当前 ego pose
***T***<sub>*t*</sub>、上一时刻场景记忆 ***M***<sub>*t*</sub>，以及写回时
需要保存的类别、不确定性和融合特征。补充材料把逻辑状态描述成
80 feature + 18 class + 2 flow + 1 log variance 共 101 channels。

**内部变换：** 先把当前自车坐标网格通过 pose 映射到 scene coordinate，
再用 grid sampling 读出当前视野对应的历史区域；融合完成后，把同一空间位置
的状态按网格索引更新，而不是生成一份新的整帧 history。

**输出：** 供 attention 使用的历史特征 ***H***<sub>*t*</sub>，以及供下一帧
继续读取的更新记忆 ***M***<sub>*t*+1</sub>。固定源码实际把它拆成
`global_feats`、`global_pred_distribs`、`global_au`、counts 和 masks；
flow 只跨相邻帧暂存，不是一个完整 scene-grid flow buffer。

**为什么这样设计：** **[判断]** 这是本笔记根据前述瓶颈与论文结构所做的
因果重建，不是作者原句：为了避免 recurrent 历史被反复变换，也避免 stacked
方案随帧数线性保留多份稠密体素，最自然的结构选择是把“历史地址”从帧编号
改成真实场景位置，使长期历史可以在一份地图中局部读写。

**训练信号：** **[论文/源码]** memory 没有独立的“地图损失”；融合表示通过
Occupancy 与 uncertainty 路径训练，跨帧 buffer 在源码中还包含 detach /
indexed write。默认配置令 flow head 从 detached feature 预测，因此 flow L1
训练 flow branch 自身，但不反向训练 memory / attention 主干；训练时下一帧
attention 读取的是上一帧 GT flow。来源：论文 §4.1 与 §4.5，PDF p. 3–6；
[固定 SHA flow head 配置](https://github.com/matthew-leng/ST-Occ/blob/1633f62e2e6677a5fa474905977acfeca4e7819e/occupancy_configs/st_occ/stocc-r50-256x704-36e.py#L273-L311)。
[固定 SHA 的实际 feature detach](https://github.com/matthew-leng/ST-Occ/blob/1633f62e2e6677a5fa474905977acfeca4e7819e/mmdet3d/models/stocc/heads/occupancy_head_w_au.py#L298-L302)。

**作用与证据：** **[论文]** Table 3 的效率受控对照中，unified 方案的
fusion time 为 24 ms、
inference memory 为 5.57 GB、整体 8.65 FPS，均优于作者实现的 recurrent /
stacked 对照；但论文没有把“memory 存储方式”和“memory attention”做完全
独立的精度消融。来源：论文 Table 3，PDF p. 7。

**论文位置：** **[论文]** Figure 2–3 与 §4.1，PDF p. 3–5。

**源码入口：** **[源码]**
[`register_scene_buffer` / `update_global` @ 固定 SHA](https://github.com/matthew-leng/ST-Occ/blob/1633f62e2e6677a5fa474905977acfeca4e7819e/mmdet3d/models/stocc/detectors/stocc.py#L212-L380)。

#### 创新模块 2：Memory Attention

**位置与接口：** 它接在当前特征 ***V***<sub>*t*</sub> 与 Occupancy head
之间，同时读取由 scene memory 返回的历史特征 ***H***<sub>*t*</sub>。

**输入：** 当前表示、同一场景位置的历史表示、位置编码，以及由类别状态、
feature similarity、不确定性和 flow 构成的 temporal attributes。

**内部变换：** 论文使用三层 temporal self-attention；固定配置每层有
8 个 heads、每个 reference point 取 4 个 sampling points。当前表示作为
query，历史表示作为 key / value，flow 改变历史采样位置，uncertainty gate
决定当前分支与历史分支各占多少，再由可变形注意力聚合。

**输出：** 融合后的 temporal-conditioned representation
***Ṽ***<sub>*t*</sub>，供预测 heads 使用并参与后续 memory 写回。

**为什么这样设计：** **[判断]** 这是本笔记根据前述瓶颈与论文结构所做的
因果重建，不是作者原句：仅有场景记忆只能“保存历史”，还不能判断某个历史
位置与当前 voxel 是否相关，因此需要把检索、动态位置修正和可信度加权放进
一个可训练 attention 接口，让模型选择性使用长期状态。

**训练信号：** **[论文/源码]** attention 没有单独标签，梯度来自融合输出上的
Occupancy 与 uncertainty NLL 路径；前 3 epochs 暂停时序分支。默认 flow
head 对输入 feature 执行 detach，故 flow L1 只训练 flow branch，并不回传
到 temporal attention。来源：论文 Eq. (16)–(18) / §5.2，PDF p. 5–6；
[固定 SHA 的 detach](https://github.com/matthew-leng/ST-Occ/blob/1633f62e2e6677a5fa474905977acfeca4e7819e/mmdet3d/models/stocc/heads/occupancy_head_w_au.py#L298-L302)；
[固定 SHA 的 flow L1](https://github.com/matthew-leng/ST-Occ/blob/1633f62e2e6677a5fa474905977acfeca4e7819e/mmdet3d/models/stocc/heads/occupancy_head_w_au.py#L339-L342)。

**作用与证据：** **[论文]** Table 4 的直接消融从 No Temporal 37.39 提升到
Mem. Attn. 41.17，增加 3.78 mIoU；这是所有新增组件里最大的主效应，但仍是
memory 与 attention 组合路径的证据。来源：论文 Table 4，PDF p. 8。

**论文位置：** **[论文]** Figure 3–4 与 §4.3，PDF p. 5。

**源码入口：** **[源码]**
[`VoxelFormerEncoder` @ 固定 SHA](https://github.com/matthew-leng/ST-Occ/blob/1633f62e2e6677a5fa474905977acfeca4e7819e/mmdet3d/models/stocc/temporal/encoder.py#L229-L378)。

#### 创新模块 3：Dynamic Awareness 与 Occupancy Flow

**位置与接口：** 它位于历史特征进入 deformable attention 之前，并在
Occupancy head 旁增加 flow prediction branch。

**输入：** 上一帧体素位移 ***f***、当前/历史 sampling position、动态实例
标注构造的训练真值，以及需要对齐的历史 3D 特征。

**内部变换：** flow 先把历史采样中心从 ***p*** 移到 ***p*** + ***f***，
attention 再在修正后的位置预测 offsets 与 weights；训练时下一帧采样使用
前一帧 GT flow，测试时则递推使用前一帧 predicted flow。

**输出：** 动态补偿后的历史采样特征，以及供下一时刻使用的两通道 flow
预测；它解决物体自身移动，不能替代 ego-pose alignment。

**为什么这样设计：** **[判断]** 这是本笔记根据前述动态错位瓶颈与论文结构
所做的因果重建，不是作者原句：只按 ego pose 对齐只能消除自车运动；真实
车辆或行人仍会从旧 voxel 移到新 voxel。为了避免在旧位置读出“幽灵目标”，
需要显式预测位移并先移动历史采样地址。

**训练信号：** **[论文/源码]** flow 用 L1 loss 监督。论文称真值来自实例
3D bounding-box 跨时间 offset；代码实际读取 annotation 的
*v*<sub>*x*</sub>、*v*<sub>*y*</sub> 并栅格化到 voxel。训练读 GT flow、
测试递推 predicted flow，形成需要额外压力测试的 exposure gap。来源：
论文 §4.5 / §5.2，PDF p. 5–6。

**作用与证据：** **[论文]** Table 4 的组件消融中，在 41.17 的 Memory
Attention 上加入 Dynamics 后为 41.73，增加 0.56 mIoU；该单次结果没有
多 seed 误差条。来源：论文 Table 4，PDF p. 8。

**论文位置：** **[论文]** Figure 4、Eq. (12) 与 §4.3，PDF p. 5。

**源码入口：** **[源码]**
[`TemporalSelfAttention` @ 固定 SHA](https://github.com/matthew-leng/ST-Occ/blob/1633f62e2e6677a5fa474905977acfeca4e7819e/mmdet3d/models/stocc/temporal/temporal_self_attention.py#L142-L331)。

#### 创新模块 4：Uncertainty-aware Gate

**位置与接口：** 它位于 memory attention 的当前/历史双分支融合点，并由
Occupancy head 的 log-variance branch 提供不确定性状态。

**输入：** 论文写历史 class activation ***c***、平均 log variance *δ*、
当前/历史 feature cosine similarity *ε*；固定代码还显式加入 observation
count、distance、18 维历史类别分布、前后各 80 维 feature 与 aleatoric
uncertainty，再把 feature 映射后计算 similarity。

**内部变换：** 论文用隐藏宽度 64→32→16→1 的四层 MLP 把 temporal
attributes 编码为 gate *u*，再混合当前与历史分支；固定代码还执行
softplus、指数和空间归一化，因此实现变量不能与论文 *δ* / *u* 逐值等同。

**输出：** 每个 voxel 的融合权重与 uncertainty-aware feature，同时
log-variance head 输出用于训练和下一时刻状态更新的不确定性。

**为什么这样设计：** **[判断]** 这是本笔记根据前述不可靠证据瓶颈与论文
结构所做的因果重建，不是作者原句：遮挡、远距离和光照变化会让不同帧的证据
质量不同；如果一律平均，新噪声会污染历史、旧错误也会压制新观察，因此需要
根据类别、相似度与不确定性决定“这次该信当前还是历史”。

**训练信号：** **[论文/源码]** 论文使用 Gaussian NLL 风格损失约束
log variance；固定代码实际采用正确类别负对数概率的 variance-weighted
分类版本。两者思想相近但公式不同。来源：论文 Eq. (17) / §4.5，PDF p. 5–6。

**作用与证据：** **[论文]** Table 4 的组件消融中，Uncertainty 在 Memory
Attention 上增加 0.68 mIoU；Dynamics 与 Uncertainty 同时加入增加 0.96，
而不是 0.56+0.68，因此不能把两项增益线性相加。来源：论文 Table 4，
PDF p. 8。

**论文位置：** **[论文]** Figure 4、Eq. (11)–(12) 与 §4.3，PDF p. 5。

**源码入口：** **[源码]**
[`UncertaintyEstimator` @ 固定 SHA](https://github.com/matthew-leng/ST-Occ/blob/1633f62e2e6677a5fa474905977acfeca4e7819e/mmdet3d/models/stocc/modules/uncertainty.py#L7-L46)。

> [!IMPORTANT]
> **[判断] 如何评价创新强弱：** 论文的结构创新不是“把 memory、flow 和
> uncertainty 三个热词拼在一起”，而是从 dense 3D 时序融合的三个耦合障碍
> 推出一条一致的数据路径：场景坐标解决历史存放地址，flow 解决动态读取地址，
> uncertainty 决定读取结果的可信度。现有证据最有力地支持 memory-attention
> 主体；两个小分支的独立贡献较小且缺少多 seed 统计。

想继续核对这些结构在固定提交中的真实张量、状态读写和论文—代码差异，可直接
跳到 [第 4 节源码审计](#4-对源码公式如何落地)。

**纯文字读法：** 下一时刻 memory 的类别状态，等于“*α* × 当前类别激活，再加上
(1 − *α*) × 同位置历史类别状态”经过 softmax。

论文实现设置 *α* = 0.5。这意味着新旧 activation 在进入 softmax 前
各占一半，但**不等于**直接平均两个已经归一化的概率分布。

**玩具例子：** 当前观察更像 car，历史记忆更像 truck。Eq. (7) 先混合两组
class activation，再由 softmax 得到相对分布。若两边冲突很强，输出如何变化
还取决于完整 activation 数值，而不是只看“各 50%”这句话。

### 2.4 mSTCV：稳定不等于正确

先看一个反例。某个静态 voxel 的真值连续两帧都是 `car`：

| 模型 | 历史预测 | 当前预测 | 是否变化 | 是否正确 |
|---|---:|---:|---:|---:|
| A | `truck` | `truck` | 否 | 两帧都错 |
| B | `car` | `truck` | 是 | 一帧对、一帧错 |

若只惩罚变化，A 看起来更“稳定”，但它是 **stable but wrong**。因此 mSTCV
必须与 mIoU 一起读。

**分三步读：**

1. ‖*y*<sub>*i*</sub> − ŷ<sub>*i*</sub>‖<sup>2</sup> 是样本 *i* 的平方残差；
2. *s*<sub>*i*</sub> 是预测的 log variance，exp(−*s*<sub>*i*</sub>) 会给残差项降权；
3. 末尾的 + *s*<sub>*i*</sub> 又会惩罚无约束地扩大 uncertainty。

**学生类比：** 面对模糊路标，学生可以说“这题我不太确定”，老师会降低这道
错题的惩罚；但如果每道题都说“不确定”，额外的 *s*<sub>*i*</sub> 代价会让总分变差。

**数值直觉：** 先只看 Eq. (17) 圆括号内部：当 *s* = 0 时，残差因子为 1；
当 *s* = ln 4 时，残差因子变为四分之一，同时括号内增加 ln 4 的
不确定性代价。整条式子外面还有二分之一，因此完整 loss 中对应的残差系数
分别是二分之一和八分之一，不确定性代价是 (ln 4) / 2。这个例子只解释公式，
不是论文实验结果。

> **公式来源：** **[源码] 非论文原式。** ST-Occ commit `1633f62e`，
> `occupancy_head_w_au.py` L23–69 与 L289–296。
> [固定源码](https://github.com/matthew-leng/ST-Occ/blob/1633f62e2e6677a5fa474905977acfeca4e7819e/mmdet3d/models/stocc/heads/occupancy_head_w_au.py#L23-L69) ·
> [可复制 TeX](../../assets/notes/2026-07-24-st-occ/formulas/source.tex#L149-L163)。

**纯文字读法：** 代码 loss 对有效体素 *i* 求均值；数据项是“正确类别
负对数概率除以两倍 variance”，正则项是“二分之一 log variance”。

**公式为可读性省略的实现细节：** 代码只保留 `target != 255` 的有效 voxel，
并在取对数和相除前把 `p` clamp 到 `[1e-8, 1]`、把 `v` clamp 到
`[1e-6, 1e6]`。因此两张图表达的是核心 loss 结构，不应被称为所有数值下的
逐值等价式。

**严谨结论：** 论文 Eq. (17) 使用平方残差；发布代码使用正确类别的负对数
概率。两者都体现“数据项按 variance 降权 + log variance 正则”的思想，
但不能说代码逐字实现了 Eq. (17)。

**统一来源锚点：** 论文 §4.5 与 §5.1–§5.2，PDF p. 5–6；固定 SHA 的

### 3.3 先会读 mIoU：42.13 不是“准确率 42.13%”

对某一类别，IoU 是“预测区域与真值区域的交集”除以“两者并集”；mIoU 是对
多个语义类别的 IoU 求平均。因此正确表述是“mIoU 为 42.13”，不能写成
“所有 voxel 的准确率是 42.13%”。

![ST-Occ Table 1：Occ3D 上不同 Occupancy 方法的主结果](../../assets/notes/2026-07-24-st-occ/table-1-main-results.png)

> **原图出处：** Leng et al., ICCV 2025, Table 1，PDF p. 6 /
> proceedings p. 26574。[官方 PDF](https://openaccess.thecvf.com/content/ICCV2025/papers/Leng_Occupancy_Learning_with_Spatiotemporal_Memory_ICCV_2025_paper.pdf)。
> 此处截取原表左侧主结果与少量相邻类别列；完整类别结果见官方 PDF。

按四步读这张表：

1. 找相同或明确对应的 backbone；
2. 分清 no-temporal、原 temporal 和 ST-Occ；
3. 计算**绝对 mIoU 点数差**，不要误写成相对百分比；
4. 看第二个 backbone 是否方向一致，再检查有没有跨域和多 seed。

三个决定结论的对照：

- FB-OCC：ST-Occ 42.13，原 temporal FB-OCC 39.11，绝对提高 **3.02**；
- FB-OCC：ST-Occ 42.13，no-temporal FB-OCC 37.39，提高 **4.74**；
- ViewFormer：ST-Occ 42.30，原 temporal ViewFormer 41.44，
  no-temporal ViewFormer 37.80。

**[论文] 支持：** 在作者的 Occ3D 设置中，ST-Occ 在两类基础架构上都带来
方向一致的收益；它不是只对单一 backbone 有效。

**[判断] 不支持：** 两组结果仍属于同一数据域和任务设置，没有恶劣天气、
传感器故障、跨域、随机种子方差或置信区间，不能写成“各种环境下都有效”或
“已经证明通用泛化”。

### 3.4 Table 2：时间更稳，但不要把“相对下降”说成“准确率提高”

![ST-Occ Table 2：FB-OCC 与 ST-Occ 不同组件的 mSTCV 对比](../../assets/notes/2026-07-24-st-occ/table-2-temporal-consistency.png)

> **原图出处：** Leng et al., ICCV 2025, Table 2，PDF p. 7 /

FB-OCC 的 mSTCV 是 12.18%，完整 ST-Occ 是 8.68%：

- 绝对下降：12.18 − 8.68 = 3.50 个百分点；
- 相对下降：3.50 / 12.18 ≈ 28.7%。

正确说法是“mSTCV 相对下降约 28.7%”，不是“准确率提高 28.7%”。

表中的 mSTCV† 表示**不使用 voxel visibility mask** 的版本，带 dagger

**[论文] 支持：** 作者发布口径下的时序不一致指标降低；结合发布代码，应

### 3.6 Table 4：最大收益来自 memory 主体，小组件收益不能线性相加

![ST-Occ Table 4：memory attention、dynamics 与 uncertainty 的组件消融](../../assets/notes/2026-07-24-st-occ/table-4-component-ablation.png)

> **原图出处：** Leng et al., ICCV 2025, Table 4，PDF p. 8 /
> proceedings p. 26576。[官方 PDF](https://openaccess.thecvf.com/content/ICCV2025/papers/Leng_Occupancy_Learning_with_Spatiotemporal_Memory_ICCV_2025_paper.pdf)。
> 此处截取原表左侧设置、mIoU 与少量相邻类别列；完整类别结果见官方 PDF。

沿 mIoU 第一列逐层读：

- No Temporal → Memory Attention：37.39 → 41.17，增加 **3.78**；
- Memory Attention → +Dynamics：41.17 → 41.73，增加 **0.56**；
- Memory Attention → +Uncertainty：41.17 → 41.85，增加 **0.68**；
- Memory Attention → 两者都加：41.17 → 42.13，增加 **0.96**。

**[论文] 最有力的组件归因线索：** 最大增益来自 memory attention 主体，
flow 和 uncertainty 在其上提供较小、方向一致的补充。

**不要做线性归因：** 0.56 + 0.68 = 1.24，但两者同时加入的增益为 0.96。
模块之间可能有重叠或交互，不能把单独消融的增益当成互相独立、可以简单相加的

**[判断] 统计边界：** 0.28–0.68 量级的小差异没有多 seed 方差或置信区间，

### 3.7 把证据分级，而不是给论文一个模糊总分

**Strong：**

- scene-centered unified memory 的结构主张；
- Occ3D 主结果和 no-temporal / temporal 对照；
- memory attention 是消融中的主要增益来源；
- 作者实现中 unified 路线的效率比较。

**Medium：**

- dynamics 与 uncertainty 的互补作用；
- mSTCV 改善代表作者口径下更少 flicker；
- 小组件收益与具体效率比例：作者实验提供了支持，但跨实现复现仍未核验。

**Weak / 未覆盖：**

- 跨域、恶劣天气和传感器故障；
- 故障结束后的恢复时间；
- uncertainty calibration；
- stable-but-wrong 的持续时间；
- predicted-flow 误差随历史长度是否累积；
- checkpoint 独立复现和多 seed 统计。

## 4. 对源码：公式如何落地

固定版本：
[`1633f62e2e6677a5fa474905977acfeca4e7819e`](https://github.com/matthew-leng/ST-Occ/commit/1633f62e2e6677a5fa474905977acfeca4e7819e)。

先按论文的信息流打开源码：

```text
多相机图像
→ ResNet-50 / CustomFPN / CM_DepthNet
→ LSS forward + BEVFormer backward projection
→ 当前 voxel feature
→ scene buffer 读取当前 RoI
→ flow-conditioned temporal attention
→ uncertainty-aware fusion
→ scene buffer 写回
→ 3D ResNet-18 / FPN3D
→ occupancy / uncertainty / flow heads
```

### 4.1 先钉住继承的前后端：什么不是 ST-Occ 的创新

- **[源码] 图像前端：** ResNet‑50 stage 3/4 → CustomFPN → CM_DepthNet；
  ImageNet 权重和 FB‑OCC depth-pretrained checkpoint 都在固定配置中声明。
- **[源码] 视角变换：** LSS 3D forward projection 先 lift 多相机 feature，
  一层 BEVFormer-style backward projection 再用 image feature refine，
  两路相加形成当前 100×100×8×80 表示。
- **[源码] 预测后端：** temporal fusion 后接 CustomResNet3D‑18、FPN3D、
  learned multi-scale weights 和上采样，最后并行输出 19-channel raw logits、
  per-class variance 与两通道 flow；推理丢弃额外 void channel 后得到 Occ3D
  的 18 类输出。

### 4.5 Uncertainty gate 与 loss：论文思想、代码语义要分开

这里有三组不能无缝等同的对象：

1. **Uncertainty 表示。** 论文写平均 log variance *δ*；代码经过
   `softplus → exp → 类别均值 → 空间 min–max normalization` 得到
   `global_au`，estimator 又读 `1-global_au`；
2. **Gate 语义。** 论文 Eq. (12) 把 *u* 放在历史分支；默认代码路径整理后
   是 `history × (1-u) + current × u`；
3. **NLL 形式。** 论文是平方残差的高斯 NLL 风格；代码是正确类别负对数概率
   的 variance-weighted 分类版本。

**[判断] 严谨措辞：** 它们共享设计思想，但不是逐值、逐项、逐符号等价。
在 checkpoint 数值追踪前，最稳妥的结论是“变量语义有差异，需要复现时分别
报告”，而不是“代码写错”。

### 5.3 笔记分析与研究启发

**[笔记解释]** 下面把作者结论、架构、消融和源码差异重新组织成读者可以
复述的设计原则：先记“历史怎样寻址”，再区分“去哪里读”和“应该信多少”。

**[判断]** 下面的故障后效、stable-but-wrong、flow exposure gap 与最小测试
是本笔记基于公开证据提出的分析，不是作者已经证明的结论，也不能在完成相邻
文献碰撞检索前直接写成“学界尚未解决”。

#### 5.3.1 学完必须记住的三点

1. **[论文] 方法核心：** scene-centered unified memory 把长历史从显式
   dense frame queue 变成一份按真实场景位置寻址的递推状态；
2. **[论文] 最强证据：** Occ3D 主结果、no-temporal / temporal 对照、
   mSTCV、效率和消融共同支持该设计在作者设置中有效；
3. **[判断] 最大边界：** 单一数据域、缺少 seed 方差与故障恢复实验，而且
   gate、uncertainty loss 和 mSTCV 的发布代码口径都不能与论文公式逐字等同。

如果只能记一句话：

> ST-Occ 把多帧历史压进一张会持续读写的 3D 城市记忆；这提高了作者设置中的
> 时序融合效果，也让“错误是否会被写入并持续传播”成为必须额外评估的问题。

#### 5.3.2 六条可以迁移的设计原则

##### 原则 1：历史的地址不一定是时间，也可以是世界位置

ST-Occ 提醒我们：若任务有稳定空间坐标，历史不一定按“第几帧”存，也可以按
“未来检索真正需要的物理地址”存。这一原则可迁移到长期地图、流式 3D 感知、
tracking 和动态地图更新，但具体收益仍需按任务验证。

##### 原则 2：把“在哪里读”和“信多少”拆开

pose / flow 决定 read address，uncertainty / similarity 决定 trust，
attention 决定邻域聚合。把这三类职责分开，能让 failure analysis 更清楚。

##### 原则 3：论文图中的 state 必须做源码级完整性审计

一个 memory 方框不等于一个 tensor。做 reset、snapshot、restore、故障恢复
或状态删除时，应先枚举所有 future-relevant persistent fields。

##### 原则 4：时间一致性必须与正确性、响应性一起报告

低 flicker 可能是 correct-stable，也可能是 wrong-stable。可靠评测应同时看
正确性、稳定性、对真实变化的响应和错误后的恢复。

##### 原则 5：训练时 oracle 辅助信息要检查 exposure gap

若训练时可用 GT flow、测试时递推 predicted flow，应检查误差是否随序列长度
放大。这个原则同样适用于 teacher forcing、自回归 world model 和 association。

##### 原则 6：效率要拆成模块时间、整体吞吐和状态规模

fusion time、FPS、inference memory 和持久 state size 描述不同对象。自己的
论文应分别报告，不能让一个数字代替整个系统成本故事。

#### 5.3.3 论文目前没有回答的三个问题

下列问题由论文结构或源码自然引出，但“本文没有回答”不等于“学界没有答案”；
它们必须再做相邻文献检索和最小实验，才能成为创新主张。

##### 问题 1：错误历史会不会形成故障后效

- **已知：** ST-Occ 使用 persistent scene memory 和递推写回；
- **未知：** 相机冻结、黑屏或错位结束后，错误 memory 会持续影响几帧；
- **最小测试：** clean prefix → 1/3/5/10 帧故障 → clean suffix，同时测
  mIoU、state divergence 和恢复时间；
- **不能提前声称：** persistent memory 一定造成长期污染。

##### 问题 2：低 mSTCV 会不会掩盖 stable-but-wrong

- **已知：** 作者发布口径下 mSTCV 从 12.18% 降到 8.68%；
- **未知：** wrong-stable voxel 的比例和错误持续长度；
- **最小测试：** 统计 correct-stable、wrong-stable、correct-flicker、
  wrong-flicker 四类及持续时间；
- **不能提前声称：** 更稳定就一定更安全或更正确。

##### 问题 3：predicted-flow 误差会不会递推放大

- **[源码] 已知：** 训练与测试可使用不同 flow 来源，测试把预测 flow 留给
  后续时刻使用；
- **未知：** flow error 是否同时改变采样位置和写回内容，并随历史增长累积；
- **最小测试：** GT-flow、predicted-flow、no-flow 三组按连续运行帧数画
  mIoU、采样偏差和 state drift；
- **不能提前声称：** 静态代码风险已经在官方设置中造成实测退化。
