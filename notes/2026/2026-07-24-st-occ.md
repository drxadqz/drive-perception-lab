1. **[论文]** ST-Occ 的主要结构创新是把历史状态放到 scene coordinates，

## 10 分钟理解

### 1. 问题、假设与论文贡献

**[论文]** 3D Occupancy feature 比 BEV 多一个高度维度。直接堆叠多帧 voxel
feature，显存与计算会随历史长度增长；动态物体、遮挡和不确定观测还会破坏
简单的时序对齐。

论文提出的解决思路可以压缩为三步：

1. 用 scene-centered memory 给静态世界位置一个稳定地址；
2. 每帧只读取当前 ego region 对应的 memory，再把融合结果写回；
3. 使用 motion、visibility、class distribution 与 uncertainty 调整时序融合。

**[论文]** 作者主张的贡献包括统一的 spatiotemporal memory、对 Occupancy
backbone 的可迁移性、较好的长历史扩展性，以及更好的 mIoU、mSTCV 与效率。

**[判断]** 实验较好支持“在作者的 Occ3D 设置中有效”，但不足以支持更宽泛的
部署鲁棒性或跨数据域泛化主张。

### 2. 方法数据流

```text
6 路 256×704 相机
→ ResNet-50 + FPN
→ camera-aware depth head
→ LSS-style forward projection
→ BEVFormer-style backward projection
→ 当前 voxel feature：100×100×8×80
→ 从 scene memory 采样当前 ego RoI
→ 3 层 temporal deformable self-attention
   ├─ visibility / distance / class distribution
   ├─ aleatoric uncertainty
   └─ occupancy-flow displacement
→ 融合后的 voxel feature
→ 写回全局 scene memory
→ 3D ResNet/FPN
→ occupancy、uncertainty、flow heads
```

**[源码]** 六路相机在进入持久 memory 前已经融合成一个 voxel feature；官方
实现没有公开“某个 memory voxel 来自哪一帧哪一路相机”的细粒度来源映射。

### 3. 关键机制

论文对状态更新的概念表达为：

$$
\widetilde F_t
=
\psi\!\left(F_t\mid\chi[M_t,T_t]\right),
\qquad
\chi[M_{t+1},T_t]
=
\widetilde F_t ,
$$

其中 \(M_t\) 是 scene-centered memory，\(T_t\) 定义当前 ego region 在场景
坐标中的位置，\(\chi\) 负责采样和写回。

**[论文]** memory 相关通道包括 80-channel historical representation、
18-channel historical class activation、2-channel occupancy flow 和
1-channel averaged log variance。补充材料说明 temporal self-attention
使用三层，每个 deformable-attention reference point 使用四个采样点。

**[源码]** 更新并不是简单平均：attention offsets/weights、flow 和 uncertainty
gate 都依赖当前与历史 feature；class distribution 还有 decay、add 与 softmax。
因此“memory update”应被理解为一组内容相关的非线性递推，而不是一个可单独
解释的张量赋值。

### 4. 关键实验

| 论文主张 | 论文给出的证据 | 证据强度 | 主要疑点 |
|---|---|---:|---|
| Scene memory 提高 Occupancy | Occ3D 42.13 vs FB-OCC 39.11 mIoU | Strong | 单一数据域；无 seed/CI |
| 可迁移到另一 architecture | 作者复现的 ViewFormer 42.30 vs temporal 41.44、no-temporal 37.80 | Medium–strong | 仍是同任务同数据 |
| 改善 temporal consistency | mSTCV 12.18% → 8.68% | Medium | 指标依赖 GT；稳定不等于正确 |
| 比 queue/recurrent 高效 | 论文表中 memory fusion 24 ms，recurrent 705 ms | Medium–strong | 缺完整硬件与重复测量说明 |
| Dynamics 与 uncertainty 互补 | 41.17 → 41.73 / 41.85 → 42.13 | Medium | 小增益无方差 |
| 更长历史持续有益 | history-length curves | Medium | 无错误历史、恢复或顺序扰动对照 |

### 5. 论文真正证明了什么

#### 可以较有把握地说

- **[论文]** 在作者报告的 Occ3D 设置中，scene-centered memory 比列出的
  no-temporal 和多种 temporal baseline 更好；
- **[论文]** dynamics 与 uncertainty 模块有方向一致的消融增益；
- **[论文]** 长历史不需要显式保存等长 dense 3D feature queue；
- **[源码]** 官方实现确实维护跨帧 scene buffers，并按 scene sequence 训练。

#### 目前不能直接说

- “在传感器故障下鲁棒”：论文没有相应故障与恢复实验；
- “更稳定所以更正确”：mSTCV 不单独回答正确性；
- “不确定性已经校准”：没有 ECE、NLL calibration curve 或 risk–coverage；
- “可以跨域泛化”：只在同类 Occupancy 数据设置中验证；
- “已经可复现”：本仓库尚未运行 checkpoint，且训练 epoch 信息冲突。

### 6. 一般性研究启示

- scene-centered coordinates 是构建长期 3D 状态的清晰工程抽象；
- stateful 模型应显式记录完整状态集合，而不只记录论文图中的主 feature；
- 长历史收益与错误历史风险需要成对评估；
- temporal consistency 最好与正确性、校准和恢复指标一起报告；
- 训练时 GT motion 与测试时 predicted motion 的差异值得单独隔离；
- 对流式模型做复现时，scene reset、batch-slot 隔离与 snapshot/restore 和模型
  权重同样重要。

### 8. 方法与状态重建

#### 当前 RoI 如何映射到 scene memory

**[源码]** `update_global` 计算当前 ego voxel 在全局 scene grid 中的坐标，
经过 round、clamp 与 `grid_sample` 读取历史 feature。当前帧完成融合后，
`update_global_single` 把结果写回相应 scene region，并更新辅助状态。

这套设计的核心好处是场景范围可以随 ego trajectory 扩展，而每一帧只计算局部
RoI。它也意味着复现时必须正确处理：

- scene 起止与 reset；
- 每个 batch slot 对应的 scene；
- 坐标离散化与重复 index；
- dynamic flow 对后续 sampling position 的影响；
- feature 之外的 count、distribution、uncertainty 与 metadata。

#### 推理期完整状态

官方实现可见的状态包括：

- `global_feats`：scene-sized 80-channel FP32 feature；
- `global_valid_masks`、`global_vis_cnt`：validity 与 observation count；
- `global_pred_distribs`：18 类历史分布；
- `global_au`：历史 uncertainty；
- `gt_flow`：测试路径中实际保存 previous predicted flow；
- coordinate maps、scene names、scene shapes、bias 与 frame counter；
- 训练/评测路径使用的 global GT、prediction 与 mask buffers。

**[源码]** 这些状态多为普通 Python attributes，而非统一进入标准
`state_dict` 的显式 state object；仓库也没有完整的 snapshot/restore API。

#### 粗略内存尺度

默认 local feature 为：

$$
100\times100\times8\times80=6.4\text{M values},
$$

仅这一张量约为 24.4 MiB FP32。补充材料给出平均空间增长
\(\Delta_{\text{mean}}=3.25\)。如果只为理解量级而按 101 个相关通道粗估，
scene state 已可达到约 131 MiB/scene；真实工作集还包含 count、validity、
flow 和评测 buffers。这个数字是**[判断] 粗略量级估算**，不是作者报告的
完整峰值显存。

#### 工程风险

- **[源码] In-place/stateful 操作**：`detach_()`、indexed write、count `+=1`、
  class-distribution decay/add/softmax、uncertainty overwrite；
- **[源码] 内容相关路径**：feature cosine similarity、class distribution、
  uncertainty、attention offsets/weights、predicted flow、frame-wise uncertainty
  normalization；
- **[判断] 确定性风险**：5D `grid_sample`、round/clamp 后的 duplicate index、

- **[判断/未核验] 潜在隔离问题**：`global_frame_cnt` 看起来是模型级 scalar，

  recovery、temporal memory contamination。

#### 时间一致性与正确性

- **[论文/源码] 已观察事实**：mSTCV 改善，但指标使用 GT 辅助；
- **[判断] 未回答问题**：低 flicker 是否可能掩盖稳定的系统性错误；
- **下一步文献检索**：correctness-aware temporal metrics、persistent error、
  calibration under sequence shift。

#### Motion train/test gap

- **[源码] 已观察事实**：训练与测试路径使用的 flow 来源不同；
- **[判断] 未回答问题**：预测 motion 的误差是否会通过后续 sampling 累积；
- **下一步文献检索**：motion-conditioned recurrent state、exposure bias、
  GT/predicted/no-flow ablation。

#### Stateful inference 的可复现性

- **[源码] 已观察事实**：状态分散在多个普通 attributes 中；
- **[判断] 未回答问题**：现有 benchmark 是否充分测试 reset、snapshot/restore、
  batch-slot isolation 与跨设备确定性；
- **下一步文献检索**：stateful inference API、streaming evaluation protocol、
  deterministic sequence testing。
