## 2. Why this paper today

- **Direct relevance**：ST-Occ 在 scene/world coordinates 中维护跨帧持久
  3D voxel memory，是 SensorLedger3D 最直接的宿主候选和原生非线性对照。
- **Expected value**：它清楚展示了 scene-centered memory、sequence sampler、
  uncertainty/dynamics-aware fusion 和 long-history scaling 的完整设计。
- **Collision risk**：ST-Occ 已占据 scene-level Occupancy memory、unified
  temporal modeling、uncertainty/dynamics-aware temporal fusion 等主张。
  SensorLedger3D 的差分必须限定在延迟历史传感器写入的精确免重放撤销。
- **Implementation risk**：核心代码有 NC 许可标头且依赖旧 OpenMMLab/CUDA
  栈，适合作为固定外部 baseline，不适合复制到我们的公共仓库。

## 3. One-sentence thesis

> ST-Occ 用 scene-centered 持久 voxel memory 和 uncertainty-/motion-aware
> deformable temporal attention 替代逐帧历史队列，在 Occ3D 上同时提高精度、
> 时间一致性和效率；但其状态由传感器内容驱动的非线性覆盖式递推产生，因此
> 正好构成 SensorLedger3D 必须击败、却不能用简单 subtraction 精确撤销的
> native memory baseline。

## 4. Problem, assumptions, and claimed contributions

### Evidence stated by the paper

论文指出 3D Occupancy feature 比 BEV 多一个高度维度，堆叠多帧或保存历史
feature queue 的存储和计算代价高；遮挡、不确定区域和动态物体还会增加错位。

其基本更新可概括为：

\[
\widetilde F_t
=
\psi\!\left(F_t\mid\chi[M_t,T_t]\right),
\qquad
\chi[M_{t+1},T_t]
=
\widetilde F_t,
\]

其中 \(M_t\) 是 scene-centered memory，\(T_t\) 给出当前 ego RoI 在 scene
coordinates 中的位置，\(\chi\) 负责采样和写回。

论文描述的 memory 属性包括：

- 80-channel historical representation；
- 18-channel historical class activation；
- 2-channel occupancy flow；
- 1-channel averaged log variance。

补充材料说明 temporal self-attention 使用三层，每个 deformable-attention
reference point 使用四个采样点。

主要实验结果：

- Occ3D：ST-Occ 42.13 mIoU，FB-OCC 39.11，绝对提高 3.02；
- 作者复现的 ViewFormer：42.30 对 temporal ViewFormer 41.44，对
  no-temporal 37.80；
- mSTCV：12.18% 降至 8.68%，相对下降约 28.7%；
- 统一 memory fusion time 为 24 ms，论文表中 recurrent 为 705 ms；
- no-temporal 37.39，vanilla memory attention 41.17，加入 dynamics 为
  41.73，加入 uncertainty 为 41.85，两者同时为 42.13。

### My interpretation

真正值得借鉴的不是“又一个 recurrent tensor”，而是：

1. 把状态坐标从 ego frame 移到 scene frame，使静态物理位置有稳定地址；
2. 用当前 RoI 的读取/更新代替 \(k\)-frame dense queue；
3. 将 observation count、class distribution、uncertainty、motion 分开；
4. 让每个 batch slot 按顺序消费一个 scene，从而在 detector framework 中
   实现流式训练。

但这种紧凑性以**丢失历史写入来源和旧状态**为代价。ST-Occ 保存的是最新融合
结果，不保存“某个时刻、某路相机向当前状态贡献了什么”，所以它特别适合作为
SensorLedger3D 的动机和强负对照。

### Claims that the experiments do not fully establish

1. “Robustness”没有经过 blackout、freeze、desynchronization、extrinsic
   drift 或故障后效实验验证。
2. 较低 mSTCV 不一定更正确；sticky-but-wrong memory 也可能稳定。
3. 发布代码的 mSTCV 使用 GT static mask 和 GT flicker correction，不是纯
   prediction-only 部署指标。[Metric code](https://github.com/matthew-leng/ST-Occ/blob/1633f62e2e6677a5fa474905977acfeca4e7819e/mmdet3d/datasets/nuscenes_dataset.py#L670-L714)
4. “long-term dependency”主要由 history-length 曲线间接支持，没有做历史
   帧删除、顺序打乱或 stale-memory 对照。
5. uncertainty 没有 ECE、NLL calibration curve、risk–coverage 或 OOD
   calibration 验证。
6. 训练使用 GT flow，测试保存前一帧 predicted flow；没有单独量化
   train/test flow gap。
7. 没有随机种子、标准差、置信区间或显著性检验。
8. 只在一个数据域和同一类 Occupancy 任务上验证。

## 5. Method reconstruction

### Data flow

```text
six 256×704 cameras
→ ResNet-50 + FPN
→ camera-aware depth head
→ LSS-style forward projection
→ BEVFormer-style backward projection
→ current voxel feature: 100×100×8×80
→ sample current RoI from scene memory
→ 3-layer temporal deformable self-attention
   - content-dependent offsets and weights
   - visibility / distance / class distribution
   - aleatoric uncertainty
   - occupancy-flow displacement
→ fused feature
→ overwrite global feature memory
→ 3D ResNet/FPN
→ occupancy, uncertainty, and flow heads
→ update persistent class distribution / uncertainty / flow
```

六路相机在进入 persistent memory 前就已经融合成一个 voxel feature，发布实现
不存在相机级 transaction，也没有从 memory voxel 回溯到 camera-frame 的映射。

### Key equations and code semantics

论文概念性地用当前与历史信息形成 uncertainty gate。源码中，attention offset、
weight、flow 和 gate 都依赖 current/history sensor features；删除历史证据会改变
未来的采样位置和归一化。

源码中的 uncertainty loss 也不应被简单描述成论文公式的直接实现：它对
uncertainty logits 做 `softplus`，随后用预测 variance 重新加权分类 NLL。
[Uncertainty loss](https://github.com/matthew-leng/ST-Occ/blob/1633f62e2e6677a5fa474905977acfeca4e7819e/mmdet3d/models/stocc/heads/occupancy_head_w_au.py#L23-L69)

### Inference-time persistent state

发布代码的真实状态不只是一个 \(M_t\)：

- `global_feats`：scene-sized 80-channel FP32 feature；
- `global_valid_masks`、`global_vis_cnt`：integer validity/count；
- `global_pred_distribs`：18-class historical distribution；
- `global_au`：historical uncertainty；
- `gt_flow`：测试时实际保存 previous predicted flow；
- coordinate maps、scene names、scene shapes、bias、frame counter；
- 训练和 flicker evaluation 使用的 global GT/pred/mask buffers。

这些是普通 Python attributes，不是统一 `StreamingState`，不进入标准
`state_dict`，也没有完整 `snapshot/restore` API。

### Complexity audit

默认 local feature 是：

\[
100\times100\times8\times80=6.4\text{M values},
\]

约 24.4 MiB FP32。补充材料给出平均空间增长 \(\Delta_{\text{mean}}=3.25\)；
若按 101 channels 粗估，scene memory 本身约 131 MiB/scene。完整工作集还要
加 count、validity、flow 和 evaluation buffers，所以不能只以 80-channel
`global_feats` 作为内存基线。

## 6. Experiment logic

| Claim | Evidence | Strength | Main concern |
|---|---|---:|---|
| Scene memory 提高 Occupancy | Occ3D 42.13 vs 39.11 mIoU | Strong | 单一数据域，无 seed/CI |
| 可迁移到另一 architecture | ViewFormer 42.30 vs 41.44 | Medium–strong | 同任务同数据 |
| 改善 temporal consistency | 8.68% vs 12.18% mSTCV | Medium | 指标依赖 GT；稳定不等于正确 |
| 比 queue/recurrent 高效 | 24 ms fusion，5.57 GB inference memory | Medium–strong | 缺完整硬件和重复测量说明 |
| dynamics 和 uncertainty 互补 | 41.17→41.73/41.85→42.13 | Medium | 小增益无方差 |
| 更长历史持续有益 | history-length curves | Medium | 无错误历史/历史删除实验 |

### Missing controls most relevant to SensorLedger3D

- 单相机 blackout、freeze、extrinsic drift；
- 输入恢复后的 persistent aftereffect；
- full sensor-masked replay；
- reset、skip-write、no-memory、checkpoint replay；
- 远历史帧删除或顺序打乱；
- GT flow vs predicted flow vs no flow；
- per-camera additivity probe；
- snapshot/restore equality；
- native nonlinear raw/JVP/process-sidecar repair；
- scene-level bootstrap 和独立数据域。

### Persistent-state audit

- **In-place operations**：`detach_()`、indexed feature overwrite、count `+=1`、
  class-distribution decay/add/softmax、uncertainty overwrite。
- **Sensor-dependent paths**：feature cosine similarity、class distribution、
  uncertainty、attention offsets/weights、predicted flow、frame-wise min–max
  uncertainty normalization。
- **Determinism hazards**：5D `grid_sample`、round/clamp duplicate indices、
  indexed overwrite collision、dropout、batch-slot scene reset、plain-attribute
  state not captured by checkpoint。
- **Important possible bug**：`global_frame_cnt` is a model-level scalar rather
  than clearly isolated per batch slot; resetting one scene may affect another
  slot's relative-scale feature. This needs an executable batch-isolation test.

## 8. What transfers to SensorLedger3D

### Directly reusable ideas

1. Scene-centered state coordinates.
2. Per-scene bounds derived from ego trajectory.
3. Explicit sequence sampler and scene-token reset.
4. Temporal curriculum: train stateless/readout path before persistent memory.
5. Separate count, class evidence, feature statistics, uncertainty and motion.
6. History-length scaling curves, adapted to ledger horizon and alarm delay.
7. Static/dynamic and distance-stratified evaluation.

### Ideas requiring redesign

1. Replace overwrite memory with transaction composition.
2. Generate camera-frame transactions before cross-camera persistent fusion.
3. Move nonlinear attention to stateless read/decoder side.
4. Restrict exact transport to trusted ego/time metadata.
5. Represent uncertainty using revocable count/sum/sum-of-squares or kernel
   numerator/denominator statistics.
6. Use an explicit `StreamingState`/`StateBundle` with reset, snapshot, restore,
   add, revoke, decode and byte accounting.
7. Define deterministic reduction for multiple writes to the same world voxel.

### Designs that violate exact-revocation assumptions

- early six-camera fusion；
- overwrite-style global memory；
- content-dependent temporal transition；
- nonlinear attention, LayerNorm, softmax and residual writeback；
- flow-dependent future sampling；
- recurrent class-distribution normalization；
- whole-frame uncertainty min–max normalization；
- no old-value or camera/time ledger；
- no complete state serialization interface。

Native ST-Occ is therefore a native nonlinear baseline and aftereffect host, not
an exact SensorLedger3D implementation.

## 9. Open problems and innovation opportunities

### Opportunity A — Exact invalidation of a historical camera write

- **Observed evidence**：ST-Occ fuses cameras before nonlinear overwrite and
  keeps no per-camera ledger or inverse.
- **Inference**：a delayed invalidation requires replay in native ST-Occ.
- **Falsifiable hypothesis**：per-camera additive sufficient-statistic world
  memory can keep clean mIoU within 0.5 of the native baseline, reach FP32
  state error \(<10^{-5}\) versus the same architecture's masked rerun, and
  retain more than 90% of full-replay recovery gain.
- **Minimum experiment**：one scene, one camera, one frame, delays 1/2/4/8,
  single/multiple/order-independent deletion, native raw-subtraction negative
  control.
- **Collision search needed**：exact unlearning, process sidecars, event
  sourcing, map reintegration, factor removal and sensor-state repair.

### Opportunity B — Persistent aftereffect after sensor recovery

- **Observed evidence**：ST-Occ values long history but never injects sensor
  failures; supplement acknowledges continuous-update inconsistency.
- **Inference**：the same long memory may retain bad observations after the
  sensor recovers.
- **Falsifiable hypothesis**：blackout/freeze/extrinsic-drift faults of 1/4/8
  frames leave a measurable 2–4-frame post-recovery gap, and full masked replay
  beats reset, skip-write and no-memory.
- **Minimum experiment**：30–50 paired nuScenes validation episodes, delays
  0/2/4, fault/post-fault AUC, \(T_{90}\), recovery fraction and scene bootstrap.

### Opportunity C — Revocable dynamic-state modeling

- **Observed evidence**：flow changes future sampling paths and is predicted at
  test time.
- **Inference**：motion evidence cannot simply be treated as another removable
  feature after it has already changed transport.
- **Falsifiable hypothesis**：trusted ego transport plus revocable motion
  sufficient statistics can preserve exact deletion while keeping dynamic-class
  IoU within 0.5–1.0 of native ST-Occ.
- **Minimum experiment**：static/dynamic subsets; no-flow, GT-flow,
  predicted-flow and revocable-motion variants; joint flow error and CFGap.

### Opportunity D — CFGap versus sticky temporal consistency

- **Observed evidence**：mSTCV measures changes, not equality to a
  sensor-masked counterfactual.
- **Inference**：a frozen wrong state may score well on consistency.
- **Falsifiable hypothesis**：a sticky-memory control lowers flicker while
  worsening CFGap and post-fault regret; SensorLedger3D improves both.
- **Minimum experiment**：native, freeze, reset, full replay and SensorLedger3D;
  plot mIoU–mSTCV and recovery–CFGap Pareto.
